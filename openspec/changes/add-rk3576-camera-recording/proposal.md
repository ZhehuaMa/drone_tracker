# 生产相机实时录像提案

## Why

生产程序目前无法保存相机现场，发生识别异常后缺少可回溯的视频，也无法持续收集真实数据。电池耗尽或碰撞可能使录制突然中止，需要在不阻塞跟踪的前提下持续保存未叠加画面，并控制尚未持久保存的数据量。

## What Changes

- 为 RK3576 生产板的 SC233HGS 相机增加独立录像支路，保留相机输出的完整 NV12 画面。NV12 包含亮度与色度；录像不叠加检测框、跟踪框、文字或 OSD（屏幕显示叠加），也不额外缩放、裁剪或增强图像。相机 ISP（图像信号处理器）处理和视频有损压缩仍然存在，不宣称无损传感器原始数据。
- 使用 MPP（Rockchip 媒体处理接口）调用 H.264 硬件编码，写入 MPEG-TS 流式视频文件。按约 60 秒分段，默认每秒请求一次持久化；关键帧和真实采集时间使中断文件的有效前缀可以被通用播放器或检查器读取。
- 录像随既有相机 ON/OFF 建立和结束会话，从相机完成缓冲归还、停止及预热期限最终检查后的首个合格帧开始录制，未发现目标时也持续录制；OFF 后不继续采集。预热是交付图像前检验时间连续递增的观察期，观察帧不进入视频。通过独立 `recording.*` 启动参数启用，不复用 ROS bag（ROS 消息记录文件）的 `need_save` 开关，不增加运行期录像启停接口。
- 采用独立录像进程与有界缓冲，录像拥塞或故障不阻塞采集、跟踪与 OSD。增加状态、掉帧、持久化落后时间、磁盘空间和异常结束记录。
- 保留原始采集时间、帧序号及编码时间的对应关系。重启时识别未正常完成的文件，保留原件并报告检查结果；不把最后一次写入误报为已落盘。
- 采用模拟写入故障、文件副本截断和进程强制终止验证异常恢复。**不进行断电、拔电、强制重启或碰撞测试**；真实掉电、设备缓存行为和介质损坏后的数据保全不在已验证承诺内。

例如，ON 后先创建会话并等待相机预热；若前十帧被观察丢弃，第十一帧为首个合格帧，则录像与跟踪都从该边界开始。即使一直没有发现目标，录像仍持续；OFF 结束本轮文件。预热期间 OFF 或失败会留下零帧会话原因，不伪造视频。录像进程被意外终止时，跟踪继续运行，已写入视频仍保留供通用工具检查。

## Capabilities

### New Capabilities

- `rk3576-camera-recording`：SC233HGS 实时原画面分流、硬件编码、分段存储、周期持久化、故障隔离、时间记录和非断电验收。

### Modified Capabilities

- `rk3576-ros-camera`：增加独立录像启动参数及随 ON/OFF 的整轮生命周期，保留相机 `need_save=false` 的旧消息记录边界。
- `rk3576-sc233hgs-camera-frame-source`：允许独立 NV12 录像支路，保持跟踪 Gray8 输出、时间语义、单消费者队列和设备回收规则。
- `platform-factory`：为录像支路明确增加有界队列的例外，通过不暴露硬件类型的配置与状态接口装配，保持 Jetson、视频及 AR0234 的旧行为。

## Impact

- 依赖 `fix-sc233hgs-startup-timestamp-warmup` 提供的合格帧边界，先完成其采集实现与验证再集成录像。预热阈值和故障规则以该变更及同步后的相机主规格为准；录像不另设预热策略。预热丢弃、录像拥塞丢帧和设备缺帧独立统计，首帧前不启动基于视频输入的停滞计时。

- 主要涉及 `src/drone_tracker_node.*`、`src/platform/platform_factory.h`、`src/platform/rk3576/rk3576_camera_capture_base.*`、SC233HGS 帧源、RK3576 工厂和新增录像模块/工作进程。
- 涉及根目录及 RK3576 构建文件、相机 YAML 参数、ROS/相机测试和部署文档。MPP 与视频封装依赖只进入 RK3576 录像目标，不进入公共跟踪算法。
- 与在途 `integrate-rk3576-hdmi-osd` 共用节点和配置文件。实施时核对其最新工件与代码，保持显示独立，不能用显示输出作为录像输入。
- 正式验收目标为 HZ-RK3576_WuKong Board。继续使用系统 RKNN Runtime 2.3.2 和 RKNPU 驱动 0.9.8；不替换系统 Runtime。
- 不新增 AR0234 或 Jetson 录像功能，不改变 ROS 话题、状态数值、模型契约或跟踪仲裁。不新增 ROS bag 自动记录、低电量控制协议、循环覆盖、网络传输或掉电保护硬件。
- **不包含离线转换工具，不扩展现有回放解码能力。** 新录像不能据此宣称可直接供现有 MJPEG 回放入口使用；原始时间记录仍须保留。
- 按用户 2026-09-23 确认，本次不包含小目标、快速运动、暗光三类现场的人工画质验收和 8/12/16 Mbps 对照。默认码率保持 12 Mbps；完成本变更不代表这些场景的录像质量已验证。

- 按用户 2026-09-24 要求，生产板验收收敛为默认配置连续录像 5 分钟，覆盖跟踪、OSD、分段解码及正常启停。取消多同步周期重复性能对照、20 轮启停、30 分钟负载及大量重复实机强杀；保留基本故障隔离检查和已经完成的证据。
