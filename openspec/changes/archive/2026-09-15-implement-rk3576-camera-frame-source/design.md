## Context

当前项目只能读取录像，不能从测试相机提供公共灰度帧。本设计让独立工具稳定读取 AR0234，并验证停止和帧生命周期。动机见 proposal.md。

参考仓库 `ar0234_osd_hdmi` 的 `hw/camera.*` 使用 V4L2 多平面采集接口，但 GREY 图像实际只有一个平面。MMAP 表示把驱动缓冲区映射到进程地址空间。参考实现导出 DMA-BUF（可供设备间共享的缓冲区句柄），供显示链使用；其借用帧依赖相机对象存活，不能直接交给长期持帧的异步检测。

参考文档的工作配置是 GREY 1920×1200、60 FPS，实际行跨度 2048 字节；行跨度表示相邻两行起点的间隔，不能用图像宽度代替。参考代码未传递 V4L2 时间戳，也未完整区分超时、断流与出队错误，需要补齐。

2026-09-15 当前板端内核为 6.1.141；媒体驱动为 rkcif，`/dev/video0` 打开返回 `No such device`。用户确认相机尚未连接。因此只读检查不构成采集可用性证明，也不采用参考 README 的历史内核和性能数据作为本次验收结果。

## Goals / Non-Goals

**Goals:** 提供独立相机源、无设备故障注入测试和无模型实机工具；保留公共帧、队列及帧源控制接口。

**Non-Goals:** ROS 相机接入、触发采集、相机录像、缩放/翻转/镜像、RGA 加速、零拷贝、显示链及模型质量调优。首版拒绝对应请求，不静默忽略。

## Decisions

### 1. 在平台内实现设备会话和帧源两层

选择新增 `camera_device.*` 管理 V4L2 设备，`camera_frame_source.*` 管理线程、队列和状态。设备层允许注入系统调用替身，以测试真实资源流程。公共接口不暴露 Linux 设备类型。

不直接复制参考项目的 `CameraBase::Frame`，因为它保存相机裸指针，且析构归还缓冲失败不会上报。后果是新增少量适配代码，但共享帧能独立于设备存活。

### 2. 显式配置传感器，严格核对协商结果

公共配置末尾追加 `camera_media_device`、`camera_sensor_entity` 和 `camera_buffer_count`（默认 4）；既有聚合初始化保持兼容。设备路径、实体、宽高、整数帧率必须显式给出，缓冲数量限制为 2–32。输出尺寸只接受 0（原尺寸）或与输入相同；`trigger_mode` 必须显式 false，其公共默认值不改。

参考代码使用 `media-ctl` 设置实体 pad 0 的 `Y8_1X8` 格式及帧间隔。首版保留该工具，但使用独立参数数组启动并检查退出码、标准错误和有限超时，不拼接 shell 命令。实体名中的引号和控制字符明确拒绝。媒体路径来自配置，不执行自动探测后的猜测写入。

设备层核对 capture-mplane、streaming 能力、GREY、一个平面、逐行图像、精确宽高、stride、sizeimage 和实际缓冲长度。子设备配置后查询实际格式与帧间隔，不能把设置命令成功当作实际设置成功。驱动调整尺寸、帧率或格式时拒绝。

不引入媒体控制库或传感器私有 I²C 操作，因为参考路径已提供可复用设置方式。实际后果是运行依赖 `media-ctl`，工具缺失或超时有明确诊断。相机断电、设备树及驱动恢复属于实机准备，不由帧源自动修改。

### 3. CPU 复制有效灰度像素并及时归还驱动帧

使用 V4L2 MMAP 的 CPU 访问路径，不导出 DMA-BUF，不链接 RGA。驱动通过出队/入队交接 CPU 与设备访问所有权。校验出队 index、plane 数、data_offset、bytesused、错误标志以及可访问长度；最后一行所需长度按 `(height-1)*stride + width` 检查溢出。

单帧流程：

1. `poll` 等待设备可读或停止事件。
2. `DQBUF` 取出驱动帧并校验元数据。
3. 在驱动帧仍归本进程持有时，将有效灰度逐行复制到 `HostFrame`。
4. `QBUF` 归还驱动帧；失败时记录错误并结束当前轮，不发布未确认完成的帧。
5. 以非扩容方式尝试放入既有队列；满时丢弃新帧。

例如，1920×1200、stride=2048 的帧每行只复制 1920 字节，128 字节填充不进入输出。持有输出帧不延迟驱动缓冲归还。

不选择零拷贝，因为检测和补帧缓存可能长期持帧，耗尽有限驱动缓冲。代价是每帧一次主机复制；报告实测复制耗时和吞吐量，后续再评估优化。

### 4. 保留设备时间，并提供有标记的回退

每轮启动记录 `CLOCK_MONOTONIC` 与 `CLOCK_REALTIME` 的配对样本；前者用于不受校时影响的间隔，后者对应系统日期时间。采样采用单调时钟前后夹取系统时钟并记录采样跨度，用中点计算固定偏移。

当缓冲明确标记 `V4L2_BUF_FLAG_TIMESTAMP_MONOTONIC` 时，使用驱动时间加本轮固定偏移。保留原时间戳、flags 和帧 sequence；SOE/EOF 标志分别表示曝光开始/帧结束，报告实际来源，不声称已经验证曝光同步。

对于未标明时钟域或 COPY 时间戳，使用紧随成功出队采样的单调时间加同一偏移，诊断明确标记 `dequeue_fallback`。每轮首帧确定策略；中途策略变化、时间不递增、无效 timeval 或溢出均失败，不人为补一微秒。整个轮次不因系统时间跳变重写偏移。

不把未知驱动时间猜测为系统时间，也不按配置 fps 合成帧时间。回退路径能接入实际驱动，但仅表示出队时间；后续 ROS 姿态对齐必须另行评估这一限制。

### 5. 可中断停止和安全重启

构造阶段校验配置、配置传感器、查询采集格式，随后关闭设备，不 STREAMON、不创建线程。每轮 start 重新打开与校验，申请映射并预先 QBUF 全部缓冲，再 STREAMON；该顺序与参考项目先 STREAMON 的做法不同，需要实机确认。未知驱动差异不能静默修改协议。

使用 `eventfd`（可让 poll 醒来的事件句柄）响应停止。单个生产线程拥有采集会话；控制线程只发送停止信号并 join。工作线程退出后再 STREAMOFF、解除映射、释放缓冲及关闭描述符。异常和部分启动同样按已取得资源逆序清理。STREAMOFF 失败时先关闭设备停止驱动访问，再解除映射；错误保留到状态中。

start/stop 由调用方串行调用；start 和析构前消费者必须静止，stop 可与单消费者取帧并发。队列保持当前 `BlockingReaderWriterQueue<FrameRef>(30)` 配置与 `try_enqueue` 行为。启动前回收上轮线程并重建队列，旧帧不进入新轮。已交付的共享帧继续有效。

普通 poll 超时不报 EOF；连续 2 秒没有成功出队帧记为采集超时失败，便于发现失联。停止应打断这段等待，无设备测试要求 250 ms 内完成；实机记录总停止时间，要求不超过 1 秒，并分列驱动清理耗时。

不通过强行关闭其他线程正在使用的 fd 来停止，以避免 fd 复用和设备访问竞态。代价是显式维护唤醒句柄与线程退出顺序。

### 6. 独立工厂显式开放，生产入口继续受限

`rk3576::createFactory` 追加能力选项，默认不开放相机；独立工具显式开启。`CreatePlatformFactory()` 的生产装配不启用此选项，保持 ROS 视频规格。视频、模型创建与既有调用不变。

不统一打开两个入口，因为 ROS 内参、录像与参数配置尚未覆盖真实相机。后果是独立工具可验证公共接口，下一次 ROS 接入有明确的能力开关。

### 7. 验收工具与证据分层

新增 `camera_source_driver`，显式接受设备配置、帧数/时长、循环次数、消费者延迟和新输出目录。每轮报告实际格式、时间来源、原始 sequence、丢帧统计、复制耗时、停止时延，以及进程内存、线程和描述符。只有当前帧来自同一时刻的驱动缓冲副本时，才进行逐像素对照，不能比较两次独立采集的动态画面。

工具可保存少量无损灰度快照，拒绝覆盖结果目录，不加载模型。实现单独相机目标与测试构建入口，使其不必发现 RKNN、ROS、RGA 或 DRM。既有 RK3576 构建仍按原入口回归。

不以检测成功或 60 FPS 作为本次完成门槛。完成门槛为数据完整、时间策略可核查、停止可靠、规定负载完成且无未解释持续资源增长。性能值作为测量结果。

## Risks / Trade-offs

- 相机未连接 → 先完成无设备验证和 ARM64 构建；实机任务保持未完成，连接后重新检查拓扑与设备占用。
- 驱动元数据和参考文档不一致 → 严格核对并报告实际值，不自动接受错误格式或猜测时间来源。
- 1920×1200 的主机复制有带宽成本 → 记录复制时间及慢消费行为，优化在后续变更进行。
- 传感器设置影响全局设备状态 → 使用明确配置、部署前检查占用；不停止其他程序，不修改启动服务，报告设置失败。设置成功的传感器格式保留，不声称恢复其他应用配置。
- MMAP 缓冲 CPU 可见性依赖驱动实现 → 固定图案/逐帧快照实测；如发现缓存不一致，先报告并修订设备访问设计，不能凭显示链历史验证判定通过。

## Migration Plan

1. 按任务清单实现设备层、帧源、独立工厂选项和工具。
2. 完成故障注入、公共回归与约定 ARM64 构建。
3. 用户接好相机后确认设备和传感器格式，部署独立工具进行短采集。
4. 完成 20 轮启停、100 次创建销毁和至少 10 分钟连续/慢消费负载，保存验证记录。
5. 校验规格与实现一致；本次不启动 ROS 相机、不修改模型质量任务。

回退只需停止独立工具并使用原视频入口；已有模型、视频配置和参考仓库不被修改。
