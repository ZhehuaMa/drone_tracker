# 首帧边界实施与编码兼容性验证

日期：2026-09-23。变更：`add-rk3576-camera-recording`。

## 已实施范围

用户明确要求从相机最终确认有效的第一帧开始录制。提案、设计、四份规格增量和任务已统一采用以下顺序：驱动缓冲有效时暂存完整画面，归还缓冲并完成原有停止/预热期限检查后才发布给编码器。失败或取消会撤销暂存，不改变相机检查规则。

`CameraNv12Sink` 提供非阻塞的暂存、发布、撤销边界。默认不传接收器，因此旧调用没有新增像素复制。`copyNv12` 验证完整亮度与色度平面，按实际行跨度复制有效像素；同时保留驱动色彩字段、序号和采集时间。SC233HGS 的公共灰度输入和时间逻辑保持不变，AR0234 拒绝新 NV12 接收器。

新增四槽共享内存原型和独立相机编码探测器。槽只在发布后可被读取，复制至编码器完成后释放；满时丢当前录像帧并记录区间。编码输出队列包含正在写入的数据，限制为 8 MiB。当前仅用于独立验证，没有正式子进程、ROS 配置、TS 分段、周期同步或恢复检查。共享槽的完整跨进程故障验证和丢帧区间持久保存仍未实现，相关整项任务不勾选。

## 生产板验证

使用 `firefly-production` 对应的 HZ-RK3576_WuKong Board，主机名 `hzhy`。板端 GCC 11.4.0、MPP pkg-config 1.3.9、libavformat 58.76.100，与既有 [依赖基线](board-recording-baseline.md) 一致。采集前重新读取设备列表、`/dev/media2` 拓扑和 `/dev/video22` 格式：1920×1200 NV12、stride=1920、sizeimage=3456000、全范围，其他色彩标记 Default。运行前相机无占用，持久文件系统剩余约 46 GiB。

源码和独立构建位于 `/home/hzhy/drone-recording-validation-20260923/final-confirmation` 和同级 `build-final`。本轮没有加载模型、运行跟踪/OSD或修改正式部署；系统 RKNN 库没有替换；验证后 SHA-256 仍为 `d31fc19c85b85f6091b2bd0f6af9d962d5264a4e410bfb536402ec92bac738e8`，相机无占用。

固定配置为原尺寸、60 fps、12 Mbps、H.264 Baseline。相机 PTS 使用首个已发布帧的实际采集时间为零点。每次输入与输出 PTS 一致，每秒请求 IDR 并检查实际输出；没有 B 帧。程序的 `capture_fps` 字段实际表示已录帧在其采集时间跨度中的有效帧率，发生丢帧时不能当作驱动出队帧率。

对应原始记录：[阶段计时](evidence/camera-timing-12m.log)、[中转版本](evidence/camera-parallel-12m.log)、[直接复制短测](evidence/camera-direct-12m.log)、[直接复制一分钟](evidence/camera-minute-12m.log)、[分离写盘一分钟](evidence/camera-queued-minute-12m.log)。历史探测器的排队方式不同，不能把这些顺序运行当作受控性能对照。最后一次编码输出队列峰值为 796,734 字节，单包硬件编码最长约 13.105 ms，仍有原始槽满丢帧，根因尚未确定。

600 帧真实样本通过通用 FFmpeg 完整解码；ffprobe 确认 1920×1200、全范围、无 B 帧和 600 帧，见 [流信息](evidence/camera-direct-stream.json)。一分钟样本的 3600 帧也全部解码成功，检查结果单独保存在 [流信息](evidence/camera-minute-stream.json) 与 [解码日志](evidence/camera-minute-decode.log)。视频内容可解码与零丢帧吞吐是两项不同结论。

RSS 是进程驻留内存，不能视为全部 MPP 内部或设备内存。显式原始共享槽为 13,824,000 字节，另有 3,456,000 字节 MPP 输入缓冲；MPP 内部全部资源上限尚未取得。未执行三类场景画质、8/16 Mbps 对照、ROS 联合启停、持久化、恢复、长时间跟踪/录像/OSD并发、功耗或断电测试。
