# 模型执行后端提取：实施验证记录

验证日期：2026-09-10。对象为 `rk3576` 分支当前工作区的 `extract-model-execution-backends`，工作流为 `spec-driven`（由规格约束设计与实施）。本记录不代表 Jetson 实机验收。任务清单 25/25 项完成，尚未归档。

## 实施结果

已建立平台无关的张量、同步执行器和模型级后端接口。张量是模型使用的多维数组；其描述包含实际形状、类型、连续存储布局、字节数与独立量化属性。量化属性描述整数如何对应实数，不复用预处理的像素乘加参数。

输入和输出均携带共享存储所有权。主机视图持有同一所有者，因此结果不依赖执行器继续存活。`TensorBuffer` 已迁入 Jetson 目录。准备输入通过别名共享引用适配，保留整个准备结果及其缓存租约；这不会复制图像或中间特征。租约表示旧输入仍被消费时不能重写相同缓存。

NanoTrack 后端执行模板 Backbone、搜索 Backbone、Head 的既有顺序。Backbone 是特征提取模型，Head 比较模板与搜索特征。模板重建开始时旧模板失效；搜索失败保留现有模板。Head 输出按完整形状分配分类和位置角色，不再让公共跟踪器猜测枚举顺序。

公共检测器、跟踪器、默认创建入口和压力测试创建入口已接入新接口。旧 `detail/model_calls.*` 和 `trt_engine.*` 已删除。ROS 配置、三个模型路径、检测级联顺序和公共后处理公式保持不变。

## 已批准的严重故障行为

用户选择：设备提交后若同步失败、无法确认设备停止访问存储，则输出模型身份和 CUDA 错误，以 `std::_Exit(EXIT_FAILURE)` 立即终止进程。该函数不执行栈展开或静态析构，避免在错误返回路径上提前释放设备仍可能访问的内存。

提交失败但随后同步成功时，返回执行失败，使执行器失效；后续调用返回未就绪。成功路径仍同步返回。未采用设备重置，因为它可能影响同进程其他模块。问题背景和选择记录见 `implementation-blocker.md`，该阻塞已解除。

## 张量契约来源与兼容边界

- 模型原生名称、输入输出顺序、形状、类型、格式和动态输入范围由 TensorRT 引擎读取。动态范围是模型允许变化的轴长度上下限。当前执行器使用第 0 个优化配置，不猜测 Backbone 特征尺寸或固定张量名称。
- 仅接受设备侧连续 Float32 执行张量。Float32 表示每个元素为 32 位浮点数。半精度、整数、特殊格式、主机侧张量及参与形状计算的输入输出均明确拒绝。它们不是本次整数推理或形状张量实现的范围。
- 输出先按实际输入解析形状。未解析、非正尺寸、乘法溢出与非连续步长不进入提交阶段。输入数量、两个 Head 输入和原生存储兼容性也在提交前检查。
- `[1,3,127,127]`、`[1,3,255,255]`、分类 `[1,2,15,15]` 与位置 `[1,4,15,15]` 是现有源码消费者的要求，不是本次从真实模型中检测到的属性。
- YOLO 不固定写死 `84×8400`。保留首输出选择，支持现有安全解码路径的 `[1,属性数,候选数]`，要求属性数至少为 5，候选数不少于属性数。旧解码转置分支在交换轴之前计算类别数，可能越界读取；因此本次依照不兼容输出拒绝要求，拒绝属性轴在最后且候选数更大的布局，不修改解码公式。没有实机模型证据证明任何现有引擎采用该转置布局。
- 新模型组合仍需对照真实文件确认兼容性。公共测试通过不能证明三个真实引擎已经通过这些校验。

## 已执行检查

构建平台：本地 Docker ARM64 Linux，镜像 `roc-rk3576-ros2-build:humble-arm64`。编译器 GNU C++ 11.4.0，OpenCV 4.5.4。容器使用 `--rm` 自动清理。挂载仓库为 `/work/ros2_ws/src/drone_tracker`。产物位于 `.docker-artifacts/model-verify/`，不纳入源码。

在容器内从仓库根目录执行：

```bash
cmake -S src/hybrid_tracker -B .docker-artifacts/model-verify/build \
  -DDRONE_TRACKER_PREPROCESS_TESTS_ONLY=ON \
  -DCMAKE_BUILD_TYPE=Debug -DCMAKE_EXPORT_COMPILE_COMMANDS=ON
cmake --build .docker-artifacts/model-verify/build -j4
ctest --test-dir .docker-artifacts/model-verify/build --output-on-failure
```

| 测试 | 验证内容 |
|---|---|

## 静态资源与行为审查

| 路径 | 所有权与错误处理 |
|---|---|
| 文件读取与加载 | 文件长度、完整读取、runtime、engine、context 均检查。构造失败时，已构造的成员负责释放部分资源；诊断包含模型路径。 |
| 张量分配 | 保持每次输出独立分配的映射内存策略。正尺寸和字节数溢出先校验；映射失败回收已分配的主机存储。预处理缓存的租借策略不变。 |
| 输入适配 | 在取得 Jetson 原生存储前检查具体类型。执行器核对创建时的设备编号；输入通过共享所有权保留，Head 消费不复制中间特征。 |
| 形状与绑定 | 使用名称接口 `inferShapes` 解析输出，检查实际连续步长。全部输入地址和输出地址绑定成功后才提交。预提交失败没有设备任务需要等待。 |
| 提交与同步 | 提交到同步之间没有可能抛异常的分配。两者之间输入与输出仍存活。同步成功才允许普通返回；同步无法确认停止时立即退出进程。 |
| 销毁 | 正常返回后没有未完成的本次提交。成员依次释放执行流、执行上下文、引擎和运行时。结果独立持有映射存储，执行器销毁不使已有结果失效。 |
| 参考分支对照 | `git show jetson:src/hybrid_tracker/nano_tracker.cpp` 确认模板首特征、搜索首特征、模板在前的 Head 双输入顺序。TensorRT 加载和同步路径对照参考实现，新增检查与故障退出均可归因。 |
| 公共公式对照 | 与本次修改前 `HEAD` 比较，NanoTrack 后处理段完全一致。YOLO 后处理只增加只读指针限定，去掉该限定和行尾空格后文本一致。 |

API 依据：[TensorRT 8.6.1 执行上下文文档](https://docs.nvidia.com/deeplearning/tensorrt/archives/tensorrt-861/api/c_api/classnvinfer1_1_1_i_execution_context.html) 说明名称接口的形状推导及步长查询；[CUDA 执行流文档](https://docs.nvidia.com/cuda/cuda-runtime-api/group__CUDART__STREAM.html) 说明销毁执行流不保证同步等待结束。这些文档用于静态实现核对，不证明本机运行过设备代码。
