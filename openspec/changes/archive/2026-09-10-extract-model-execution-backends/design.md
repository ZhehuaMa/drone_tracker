## Context

当前模型调用仍依赖具体设备缓冲区，无法在不理解 Jetson 内存与执行细节的情况下替换实现。预期结果是让公共检测与跟踪逻辑只消费明确的输入输出，设备执行与模型串联分别由两层后端承担。动机见 `proposal.md`。

现有 `detail/model_calls.h` 已通过构造注入隔离了检测器和跟踪器的模型调用。构造注入表示创建对象时传入其依赖，而不是由对象写死具体实现。`jetson_model_calls.cpp` 保存模板特征，并把 TensorRT 输出包装为借用存储的 OpenCV 图像头。`trt_engine.*` 同时定义引擎与 `TensorBuffer`，使 Jetson 预处理缓冲区也依赖推理引擎头文件。

张量是带形状的多维数组。当前执行输出固定按 `sizeof(float)` 分配，Head 输入没有经过预处理输入路径的完整检查。NanoTrack 公共算法通过通道数猜测两个输出的角色。源码要求模板输入 `[1,3,127,127]`、搜索输入 `[1,3,255,255]`，分类和位置输出分别为 `[1,2,15,15]` 与 `[1,4,15,15]`。这些是消费者要求，不是已读取真实模型后的检测结果。

已核对 `jetson` 参考分支：模板 Backbone 输出跨帧保留，搜索 Backbone 输出与模板特征按顺序交给 Head，设备同步后由 CPU 处理输出。现有主规格规定输入存储租约；租约表示消费者仍持有输入时不得复用对应缓存。本次保留该约定，并修改正式后端替代内部测试接入点的相关规格。

## Goals / Non-Goals

**Goals:**

- 把单模型执行与模型特有串联拆开，保持原模型调用顺序与公共后处理公式。
- 同时支持预处理输入和上一个模型输出作为执行输入，避免中间特征额外复制。
- 明确错误、动态形状、输出角色和模板状态，提供不依赖硬件的真实调用链测试。

**Non-Goals:**

- 不实现 RK3576 或其他生产后端，不实现整数推理或反量化，不增加运行时切换、异步设备执行接口或通用计算图。
- 不把图像裁剪、YOLO 解码、重复检测框过滤和跟踪状态机合并进模型后端。
- 不要求整套 ROS 程序在无 Jetson SDK 的环境构建，不迁移相机、DCF 或既有帧检查。

## Decisions

### 1. 两层接口与源码组织

**选择：** 在 `model/model_executor.h` 定义单模型执行接口 `ModelExecutor`，在 `model/model_backend.h` 定义 `YoloBackend` 与 `NanoTrackBackend`。`model/jetson/` 提供 `TensorRtModelExecutor`、`JetsonYoloBackend`、`JetsonNanoTrackBackend` 和私有张量存储。移除旧 `detail/model_calls.*` 接入点的重复抽象，迁移现有调用与测试。

**原因：** 三个模型共享执行机制，但 NanoTrack 需要两个模型和一个跨帧模板。两个粒度分别表达资源执行与模型语义。

**拒绝的替代方案：** 只给 `TrtEngine` 加虚函数，仍公开设备指针；或把两个完整检测/跟踪算法迁入平台后端。

**实际后果：** 公共算法只依赖模型级接口。Jetson 模型后端通过注入的执行器组织调用，测试可注入模拟执行器验证真实串联代码，不复制串联算法。

### 2. 张量描述与模型契约分离

**选择：** `model/tensor.h` 定义自有的形状、元素类型、存储布局、字节数和量化描述。执行器报告按模型原生顺序排列的输入输出名称和规格；动态维度另外报告可接受范围，执行结果报告实际正尺寸。图像的 NCHW 表示批次、通道、高、宽，不能用于描述所有输出。模型级契约另行描述 YOLO 属性轴与候选轴，以及 NanoTrack 特征、分类和位置角色。

量化是用整数近似实数，量化比例和零点放在独立的可选描述中。现有 `ModelInputContract::scale/offset` 仍只表示像素变换。本次 Jetson 路径只接受连续 `Float32`（32 位浮点数）存储，读取模型真实类型后拒绝不支持的类型和格式，不默认为浮点。

**原因：** 存储属性和模型语义承担不同校验任务，输入像素变换也不同于整数编码。

**拒绝的替代方案：** 复用 TensorRT 维度，或把所有张量强制标注 NCHW，或用预处理 scale 表示量化。

**实际后果：** 不虚构现有模型名称和 Backbone 特征尺寸。加载时读取真实描述，按消费者需求校验；动态输出在实际输入形状确定后、分配和提交之前完成校验。无法解析的输出拒绝执行。YOLO 不固定写死注释中的 `84×8400`。

### 3. 生命周期与输入适配

**选择：** 执行器接收按输入顺序排列的只读张量引用。每个引用带共享存储所有者，公共接口不公开设备指针。执行器输出同样携带所有者，可直接成为后续执行器输入。Jetson 内部检查具体存储类型和设备兼容性，再取得原生地址。

保留 `PreparedModelInput` 接口及其像素语义。Jetson 适配器把它转换为执行输入，并保持调用期间输入租约存活。把现有 `TensorBuffer` 移为独立 Jetson 存储类型，预处理与执行器共同使用，消除预处理对引擎头文件的依赖。

对 CPU 提供受所有者保护的只读视图；若内部使用 `cv::Mat`，把它封装在持有所有者的结果中，不公开可脱离所有者长期保留的裸视图。借用视图只在其拥有者存活期间有效。结果持有者可以比执行器存活更久，后续调用不得覆盖旧结果。

**原因：** Backbone 输出需要直接交给 Head；公共后处理需要读取最终结果，两者都需要可追踪的有效期。

**拒绝的替代方案：** `infer(void*)`、所有特征复制到普通 CPU 数组，或仅返回借用的 `cv::Mat` 集合。

**实际后果：** 保持现有 Jetson 映射内存与每次输出分配策略，不在本次新增输出池优化。无额外复制的准确含义是不为抽象增加特征数据复制，不承诺消除现有预处理复制。

### 4. 同步执行和错误边界

**选择：** 工厂返回已加载执行器或结构化错误；析构释放资源。执行结果区分加载失败、契约不匹配、平台类型不匹配、未就绪与执行失败，并附模型身份、相关张量和预期/实际属性。错误类型独立于 `PreprocessError`。对外失败结果不携带部分有效输出。

每个实例仅支持串行调用。成功返回时设备已完成读写，CPU 可读输出，消费者可释放输入租约。提交后失败必须先确认设备已结束对存储的访问。提交失败但同步成功时，执行上下文进入失效状态，后续执行返回未就绪。若同步失败而无法确认设备停止，先输出包含模型身份的致命诊断，再以 `std::_Exit(EXIT_FAILURE)` 立即终止进程，不执行栈展开或静态析构，不返回部分输出。不得用销毁执行流代替完成同步，也不重置共享 CUDA 设备。资源采用 RAII，即对象析构自动释放资源，覆盖构造中途失败与异常退出。

**原因：** 当前 YOLO 的异步是公共工作线程调度；底层推理已经同步，无需改变线程边界。

**拒绝的替代方案：** 返回设备任务句柄，让公共算法负责等待，或复用预处理错误掩盖模型故障。

**实际后果：** 除无法确认设备停止时立即终止进程外，模型后端与公共调用点把错误映射为现有失败处理：YOLO 本区域无检测，NanoTrack 初始化失败保持未初始化，搜索失败返回现有失败值且不更新框。加载失败保持现有初始化失败路径，并增加诊断。

### 5. 模型级语义与校验

**选择：** `YoloBackend` 查询输入要求并执行准备输入，返回受保护的原始预测和轴布局。Jetson 路径保持现有首输出选择；校验三维、批次为 1、有效属性/候选维度与浮点存储。沿用现有后处理支持的布局，不借本次修改布局推断数学行为；不能明确满足现有消费者约定的模型拒绝。

`NanoTrackBackend` 提供模板/搜索输入要求、`setTemplate`、`search`、`reset`。模板建立先使旧模板失效，新特征验证成功才提交。`reset` 清除模板并可重复调用。搜索失败保留已有模板；若执行器已失效，后续搜索报告未就绪。没有有效模板时，搜索在执行 Backbone 前拒绝。

Head 按现有模型输入顺序接收模板和搜索特征，并核对名称、索引、形状、类型和字节数。名称来自引擎，不猜测固定名称。两个 Head 输出必须唯一对应分类 `[1,2,15,15]` 与位置 `[1,4,15,15]`，按完整形状识别并返回具名结果；重复角色、缺失或额外输出均拒绝。模板/搜索 Backbone 的首输出保持现有选择，并校验其是否满足对应 Head 输入。

**原因：** 合法模型行为不变，同时消除原先对非法输出的弱检查。

**拒绝的替代方案：** 后端接收最终边界框、自行裁剪和更新跟踪状态，或让公共算法继续猜测 Head 输出顺序。

**实际后果：** NanoTracker 初始化与重置同时重置预处理器和模型模板。目标中心、搜索尺寸、分数计算和位置更新继续由公共算法管理。

一次搜索的数据流：

1. 公共跟踪器计算搜索区域并请求现有预处理器生成输入。
2. Jetson 模型后端校验模板有效，将输入适配到 Backbone 执行器。
3. Backbone 返回带所有权的搜索特征。
4. 模板与搜索特征通过校验后交给 Head；两者保持存活直到 Head 同步完成。
5. 后端返回具名分类与位置结果，公共算法按现有公式更新目标。

### 6. 装配与构建范围

**选择：** 用模型与预处理的局部装配函数创建匹配的 Jetson 组件，保留现有公开创建 API 和引擎路径参数。模型资源不跨跟踪器共享。公共张量校验与模型接口形成独立目标；Jetson 模型后端的串联测试使用模拟执行器，测试目标不编译设备执行实现。保留现有 `DRONE_TRACKER_PREPROCESS_TESTS_ONLY` 入口兼容性，扩展其模型测试覆盖。

**原因：** 当前只有一个生产平台，局部装配足够避免误配；现有公共测试已经可以独立配置子目录。

**拒绝的替代方案：** 本次新增完整平台工厂、运行时配置或全项目双平台构建。

**实际后果：** `hybrid_tracker.cpp` 可继续保留与模型无关的 VpiFrame 检查。构建检查针对模型公共目标与检测/跟踪公共调用链，不宣称整个算法库已经完全摆脱硬件依赖。

### 7. 验证证据分层

**选择：** 本次实施验收包括公共契约与生命周期测试、模拟执行器驱动真实模型后端、模拟后端驱动真实检测/跟踪算法、独立头文件编译、依赖扫描和资源静态审查。交付明确记录实际平台、模拟输入及未执行的 Jetson 检查。

**原因：** 当前本地没有 Jetson 工具链和运行环境，公共测试可以验证协议，但无法证明设备执行的数值等价性。

**拒绝的替代方案：** 用非目标主机测试成功推断 Jetson 已验证，或假设模型文件存在并把加载成功作为全部验收。

**实际后果：** 本次任务不以不可执行的实机检查作为完成条件；Jetson 构建、三个真实引擎的固定输入对照、录像框与状态序列、长时间压力和设备故障注入保持明确的未验证项。部署前需要另行补足，不能标为通过。

## Risks / Trade-offs

- [输出按浮点误读] → 读取真实数据类型和格式，在分配前校验，拒绝不支持格式。
- [动态尺寸未解析或字节数溢出] → 检查正尺寸、范围和安全乘法；模拟异常描述覆盖失败路径。
- [旧模板污染新目标] → 重置和模板失败都使模板失效；连续目标与失败恢复测试验证。
- [抽象导致复制或悬空] → 共享存储引用贯穿 Backbone 到 Head；测试旧结果保留、执行器销毁和输入租约。
- [故障后设备仍访问已释放内存] → 审查提交、同步和销毁顺序；标记无法在本机验证的设备故障路径。
- [范围扩大到全平台重构] → 只移动模型相关文件，保留预处理数值规则、其他平台边界和配置入口。

## Migration Plan

1. 新增公共张量、执行器与后端接口，建立契约校验测试。
2. 分离 Jetson 张量存储并适配现有预处理结果，迁移 TensorRT 执行路径。
3. 迁移两个模型后端，建立模板状态与具名输出契约。
4. 切换公共检测器、跟踪器及默认装配，迁移现有模拟测试，移除旧接入点。
5. 完成独立公共测试、构建依赖检查和静态审查，记录运行时验证缺口。

无持久数据或外部协议迁移。若新路径不能保持既定行为，整体回退本 change 的模型调用与装配修改，保留之前已完成的帧和预处理抽象，避免新旧执行路径同时管理相同设备资源。
