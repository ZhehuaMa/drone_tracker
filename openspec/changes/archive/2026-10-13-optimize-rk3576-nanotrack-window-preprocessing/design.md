# RK3576 NanoTrack 局部窗口预处理设计

## Context

目标恢复期间，程序逐张处理历史图像，新的跟踪框要等处理结束后才能发布。本设计减少每张图像中实际转换和复制的像素数量，同时保持模型输入、跟踪算法和历史补帧过程一致。动机及测量边界见 [proposal.md](proposal.md)。

当前 `rk3576::NanoTrackPreprocessor::prepare()` 负责把灰度图准备成 NanoTrack 模型输入。`Gray8` 是每像素一个 8 位灰度值；`Float32` 是 32 位浮点数。其处理顺序为：

1. 校验帧、模型输入契约和裁剪几何。模型输入契约规定数组形状、类型、排列和数值变换。
2. 取得模板或搜索输入的缓存租约。租约防止消费者仍持有的数据被覆盖。
3. 初始化模板时，通过 `TargetMean` 读取整帧灰度均值，并按既有 `cv::saturate_cast<unsigned char>` 规则保存填充值。
4. 将整帧转换成浮点图，复制为带越界填充的整帧画布，再从中取得局部裁剪窗。
5. 使用 `cv::INTER_LINEAR` 线性插值缩放。把单通道浮点结果复制为三个通道，并返回独立持有存储的 `FloatInput`。

`calculateNanoCropGeometry` 已定义窗口左上角、四侧填充和整数范围校验。`ReusableInput` 已规定同一缓存占用时返回 `InputBusy`。现有 `nanotrack_preprocess_test.cpp` 覆盖独立插值参考、奇偶窗口、行填充、均值回退和租约，需要扩展而非替换。

2026-10-12，正式 HZ-RK3576_WuKong 生产板的重建回放执行一次初始化及 24 次更新。原源码调用耗时约 603 ms；细分计时约 610 ms，预处理约 391 ms。整帧转换与边界复制分别约为 153 ms、186 ms。该重建使用 `test-01-20260929-1513` 录像中的 25 张图像，并非未压缩相机帧；未精确复现现场约 388 ms，不能据此承诺优化后的绝对耗时。

## Goals / Non-Goals

**Goals:**

- 模板和搜索共用局部窗口准备流程。只对本次窗口与原图的相交部分做灰度转浮点，不生成整帧浮点快照或整帧补边画布。
- 同一平台、同一 OpenCV 构建下，新旧路径交给模型的浮点张量逐元素精确一致。张量是带形状的数组；`NCHW` 表示批次、通道、高度、宽度顺序。
- 保留全图均值、窗口几何、浮点插值、失败类别、输入生命周期及串行调用约定。
- 在同输入、同模型、同补帧次数的生产板对照中确认收益。性能验收门槛见第 6 项决策，实际结论及原始证据保存在 `validation.md`。

**Non-Goals:**

- 不改变 `NanoTracker`、`NanoDcfTracker`、`HybridTracker` 的算法、阈值、模型调用频率、状态机或补帧过程。模板原始边长和搜索原始边长继续由公共算法计算，不改为检测框大小。
- 不将浮点缩放改成整数缩放、RGA 硬件缩放或自写插值。RGA 是图像处理硬件；使用它可能改变数值结果，本次不引入。
- 不改变 RKNN CPU 输入准备、`inputs_set`、模型原生输入类型、共享设备内存和推理后处理。
- 不改变 YOLO、Jetson、相机采集、图像队列或 ROS 发布条件。不新增配置参数、兼容开关和依赖。

## Decisions

### 1. 用原有几何构造小窗，不缩小算法搜索范围

**选择：** 继续调用现有几何函数。令源图大小为 `W×H`，返回的窗口为 `C=(x,y,n,n)`，其中 `n=original_size`。用足够宽的整数中间值求窗口与原图的交集 `S`，并保留公共函数现有的有效性和补齐画布整数范围校验。

交集位置按以下公式计算：

```text
sx0 = max(x, 0),         sy0 = max(y, 0)
sx1 = min(x + n, W),     sy1 = min(y + n, H)
交集非空的条件：sx1 > sx0 且 sy1 > sy0
源区域：S = (sx0, sy0, sx1 - sx0, sy1 - sy0)
小窗内目的区域：D = (sx0 - x, sy0 - y, S.width, S.height)
```

这里的加减先在宽整数中计算，确认非空且各边界可表示后再建立 `cv::Rect`。交集为空时，不建立无效的源或目的矩形。

**理由：** 旧路径返回的就是同一个 `n×n` 窗口。改变其构造位置不会改变窗口涵盖的图像或越界像素。

**未选方案：** 将窗口限制在图像内、改为目标框裁剪、对大窗口设置新上限。这些做法会改变搜索范围或已接受的输入。

**后果：** 完全在图像外、但通过现有几何校验的窗口仍返回均值填满的窗口。窗口大于原图时继续按原语义填充，不保证所有大窗口都有相同加速比例。

### 2. 局部转换与填充完成后，沿用原浮点缩放

**选择：** 为一次准备建立以下流程：

1. 保持现有前置校验及模板/搜索输入缓存取得顺序。模板准备仍先使旧均值失效。
2. 模板准备仍调用 `TargetMean::initialize(frame)`。均值读取失败时仍回退为 114；均值读取与窗口像素映射保持独立，不借机合并两次映射。
3. 创建 `n×n` 单通道浮点工作区。窗口存在越界部分时，先以当前填充值填满工作区；窗口完全在图像内时，完整转换会覆盖工作区，省略填充。
4. 取得源帧只读映射，执行现有尺寸、格式、地址及行跨度校验。行跨度是一行像素在内存中实际占用的字节数，可能包含行末填充。
5. 交集非空时，将源映射中的 `S` 用 `convertTo(CV_32F)` 写入工作区的 `D`。交集为空时仍取得并校验映射，以保持原有映射失败行为。
6. 释放映射后，按原 `cv::resize(..., INTER_LINEAR)` 将完整小窗缩放成模板的 127×127 或搜索的 255×255。
7. 沿用现有三通道复制和结果对象构造。仅模板准备整体成功后提交新均值状态。

例如，原图 1920×1200，窗口 `(-10,20,154,154)`：源有效区域是 `(0,20,144,154)`，写入小窗的 `(10,0,144,154)`；左侧 10 列填均值。之后缩放为 255×255，返回 `[1,3,255,255]` 的 Float32 NCHW 数据。

**理由：** Gray8 像素转浮点是逐像素操作，可以只转换交集。越界像素仍在浮点工作区中填充。缩放输入的尺寸、值和类型保持一致。

**未选方案：** 先把 Gray8 小窗缩放，再转换为浮点；对 Gray8 区域直接做不同的缩放；将整帧工作区只改为长期缓存。这些方案分别引入整数舍入、插值差异，或保留主要的整帧像素工作量。

**后果：** 初始化仍有一次全图均值读取，它不属于可移除的整帧转换开销。保留 0～255 浮点范围、`scale=1`、`offset=0`，不增加归一化。

### 3. 复用独立工作区，保持输出租约和资源边界

**选择：** 在 RK3576 预处理器私有状态中保存一个 `cv::Mat` 浮点小窗。模板与搜索串行复用该工作区，使用当前 `n×n` 尺寸。最终结果仍写入原有模板、搜索各自的 `ReusableInput<std::vector<float>>` 缓存。

**理由：** 工作区只在本次准备期间使用，输出结果持有另一份存储。复用工作区不会改变消费者读到的模型输入，也避免固定尺寸重复准备时的中间图像分配。

**未选方案：** 把源图 ROI（局部区域视图）或工作区直接交给消费者；为所有窗口尺寸保留一个无限增长的缓存集合；引入同一预处理器的并发调用。这些方案增加源映射存活时间、内存占用或并发复杂度。

**后果：** 小窗像素必须在映射释放前复制到自有存储。工作区可以在返回后被下一次调用重写，输出输入缓存则必须等最后一个租约释放后才能重写。窗口越界时每次完整填充，防止上次目标留下的像素进入本次输入。`InputBusy`、模板失败使旧均值失效、搜索失败保留已提交均值等行为继续沿用。

### 4. 以旧路径和独立参考共同验证数值等价

**选择：** 将变更前的整帧转换、补边、裁剪和缩放路径固定为仅供测试的参考实现，记录其源提交。新路径与它在同一 OpenCV 构建、同一图像及参数下逐元素精确比较。继续保留现有双精度四邻点插值参考；四邻点指线性缩放使用相邻四个源像素计算输出值，现有参考允许的误差仍为 `5e-4`。

**理由：** 旧路径用于发现操作重排造成的数值差异，独立参考用于发现新旧实现共同存在的几何或数值错误。两个检查承担不同职责。

**未选方案：** 只比较画面是否相似，或为了通过旧路径对照而放宽浮点张量容差。

**后果：** 同版本精确对照失败时，先排查坐标、工作区填充、行跨度及 OpenCV 执行路径；不得直接接受误差。测试至少覆盖：

| 类别 | 固定输入或事件 | 核对结果 |
|---|---|---|
| 几何 | 奇偶边长、分数中心、四侧及四角越界、恰好贴边 | 与旧路径同一窗口和张量 |
| 窗口覆盖 | 完全在图外、窗口大于图像、边长 1、等于输出边长、上采样与下采样 | 合法输入仍得到原结果 |
| 像素 | 常量、渐变、棋盘格、固定随机种子、产生小数的插值 | 三通道一致，范围和精确对照通过 |
| 行跨度 | 非连续行、窗口从原图内部开始、行末填充设为不同值 | 不读取行末填充，不误用整图原点 |
| 工作区 | 同尺寸先内部后越界、大窗后小窗、更换目标均值 | 无旧像素或旧均值残留 |
| 生命周期 | 保留模板/搜索结果、释放源帧、销毁预处理器 | 旧结果有效，缓存占用返回 InputBusy |
| 失败 | 空帧、错格式、错契约、无效几何、映射失败及非法映射 | 原错误类别与状态转移保持一致 |

### 5. 验证恢复过程，不修改补帧代码

**选择：** 新增 `tests/nanotracev3_performance_benchmarks/window_preprocess/` 诊断入口。将小窗对照、输入身份说明和恢复计时放在该目录，复用真实 `NanoTracker`、`NanoDcfTracker` 与 RKNN 后端。旧预处理器只由验证工具装配，不作为生产回退分支。

**理由：** 现有 `baseline` 规格只允许 MJPEG 解码和纯 NanoTrack，排除了 DCF 与卡尔曼滤波。本次恢复复现需要传入带时间戳的 25 张重建灰度图，并经过实际 NanoDcfTracker，不能把它包装成既有基线工具的结果。

**未选方案：** 修改 `baseline` 的输入与算法范围、复制跟踪算法实现、用模拟推理代替生产板模型，或更改 `catchupTracker` 来减少补帧。

**后果：** 两条恢复路径采用相同初始框、帧顺序、时间戳及 NanoDcfTracker 参数，均执行一次初始化和 24 次更新。比较每次成功标记、框、分数和模型调用次数。公共状态机继续使用现有回归测试；在固定输入与检测结果事件下，验证恢复/失败规则，而不要求优化前后 ROS 的实际发布时间相同。

输入清单从工具配置指定目录读取，不固化开发机路径。沿用本次重建输入身份：源提交 `09006db9ea11bd4fa137efc47ecb117660e0fad2`、录像 SHA-256 `11d45885dc32859c5aba16541ecc83f769ad47ba9ae66b54908b19d805d4c152`、初始框 `[756.689,461.019,39.712,36.7552]`。25 帧对应原视频索引 4146～4170（从 0 开始），逐帧时间戳和像素指纹随输入包保存。映射规则为选择不晚于处理时刻的最近录像帧，报告必须保留其重建假设。

### 6. 用同条件生产板对照验收性能，不以理论像素比例代替实测

**选择：** 在 HZ-RK3576_WuKong 生产板，用系统 Runtime 2.3.2、驱动 0.9.8 和同一组三个 NanoTrack 模型完成新旧 A/B 对照。A/B 表示一次只切换预处理路径，其他输入和工作量一致。

1. 先校验全部输入与模型指纹。在计时外解码图片、复制输入帧和加载模型。
2. 新旧路径各预热至少两批完整恢复，再正式测量至少十对批次，交替先后顺序。保存预热记录，并从正式统计中排除。
3. 固定跟踪 CPU 核心及 OpenCV 线程设置，记录 CPU/NPU 频率、温度和并发负载。本轮可按用户授权临时停止正式节点。测量结束和异常退出均恢复原服务并检查 active/running；不修改配置或触发相机。
4. 保持 `Preprocess`、`ImagePrepare` 原有计时含义。统计初始化、24 次更新、整批恢复和各阶段；计时结果写盘放在测量外，父子区间不重复累加。
5. 保存每对原始记录、批次中位数及 P95。中位数在样本数为奇数时取排序后中间项，偶数时取中间两项的均值。P95 是覆盖约 95% 样本的耗时值，采用排序后第 `ceil(0.95×N)` 项，反映较慢批次。

对指定 25 帧重建用例，验收目标为：新路径预处理批次耗时中位数不超过旧路径的 20%；整批恢复中位数降低，P95 不高于旧路径；输出与调用次数对照通过。该 80% 预处理降幅是待验证的设计目标，不是已获得结果。对其他窗口尺寸记录收益分布，不把这一目标推广为所有目标和现场恢复的保证。

**理由：** 测量已确认整帧处理占主导，小窗可以去掉相应像素工作；总恢复仍含推理、输入提交及后处理。阈值同时要求局部阶段显著改善和整体过程受益。

**未选方案：** 将窗口与整帧像素比直接换算为加速倍数、将现场 388 ms 按百分比换算、只测 resize 或只对旧报告比较而不重跑旧路径。

**后果：** 未达到目标时报告实际值及阶段差异，不跳帧、改阈值或混入 RKNN 输入优化以达标。三个实际模型指纹沿用输入包记录；同版本 SDK 不代表同模型，仍需校验二进制身份。

## Risks / Trade-offs

- **裁剪原点或交集偏移计算错误** → 沿用原几何函数，以宽整数计算交集；在四侧、四角和完全图外固定用例中与旧路径比较。
- **浮点缩放输入值相同但执行路径不同** → 同 OpenCV 构建逐元素精确对照，失败时定位差异，不放宽验收容差。
- **复用小窗保留旧边缘数据** → 部分或完全越界时完整填充；图内时必须完整写入。加入同尺寸连续切换的验证。
- **旧输入被工作区复用覆盖** → 工作区与输出缓存独立；沿用模板/搜索租约，并验证帧及预处理器销毁后的结果有效性。
- **完全图外窗口因省略映射而绕过失败** → 即使交集为空，也保留既有映射和类型校验。
- **大窗口无法获得同样收益或内存申请失败** → 保持原几何接受范围和平台失败类别，记录大窗数据，不新增截断规则。
- **更快处理改变异步结果到达时刻** → 保持请求与仲裁代码；用固定输入事件验证算法语义，区分行为条件与实际墙钟时刻。
- **现有主机快照规格被误读为必须复制整帧** → 本次仅为 NanoTrack 构造自有局部快照；YOLO 的同一帧全图快照和区域级联约束保持适用。

## Migration Plan

本变更实施代码、测试和构建，并在隔离目录完成生产板验收，不部署优化版本。

实施按 [tasks.md](tasks.md) 执行：固定旧路径参考与测试输入，完成小窗实现及数值/生命周期回归，再在生产板执行独立诊断工具。所有正确性和性能条件通过后才报告优化可用，不自动切换正式版本。

生产部署不属于本变更任务。若以后另行要求部署，按既有版本打包和回退流程执行。实现不增加配置，回退可恢复旧二进制，无需迁移模型、参数或录制数据。

## Open Questions

- 实际降幅及不同窗口尺寸的收益分布需要实施后测量。它们不改变局部窗口方案或数值等价约束。
- 现场 388 ms 的确切组成仍缺少原始输入帧身份和当日完整负载；本次接受重建回放作为优化对照，不宣称解决这项历史测量限制。
