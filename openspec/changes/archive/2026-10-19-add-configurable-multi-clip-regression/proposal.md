# Proposal

## Why

当前回归工具只能重复测试一段固定的二十秒录像，维护者无法通过一份配置比较多段录像，也无法选择每段录像的测试区间。需要支持多个独立用例，并在未填写区间时测试整段录像，以扩大修改前后的行为检查范围。

## What Changes

- **BREAKING**：回归测试公开入口改为只接收一个配置文件路径；录像列表、输入和输出路径、程序路径、重复次数及比较设置全部写入该文件。原有业务参数命令行形式不再作为公开接口。
- 配置列出一个或多个用例，每项具有唯一 `case_id`、录像及必要的逐帧时间、姿态和算法配置来源。
- 每项可选帧选择区间（frame-selection interval）`frame_selection_interval: {start_seconds: 55, end_seconds: 75}`，含义固定为源录像时间的 `[55,75)`，即包含起点而不包含终点。终点还接受显式标记 `end`，例如 `{start_seconds: 165, end_seconds: end}` 选择从 02:45 到录像结束的全部帧。它选择帧，**不是运行超时**。省略整个字段时选择源录像全部帧，不默认二十秒，也不继承前一项区间。
- 把源录像身份、区间、帧数、图像尺寸及统计窗口从固定常量改为经校验的用例记录。保留 `wlcb-1513-loss-recovery` 的原始帧选择和历史证据，不为新录像复用其身份。
- 按配置顺序串行执行各用例。每轮独立清空跟踪状态，并预解码该用例全部选中帧。保持不设置固定输入缓存内存上限；不自动截短录像或改为流式解码。
- 每个用例分别保存参考运行、冻结基线、候选运行及比较报告。基线表示显式选定且不可修改的参考运行集合；每侧仍须至少三次完整合格运行。汇总报告逐项展示结果，不跨录像混合样本或掩盖失败。
- 实施任务增加四个指定外场用例：`test-02-20260929-1605.叠框.mp4` 的全部帧，以及 `test-03-20260929-104206.叠框.mp4` 的 `[20,35)`、`[100,130)`、`[165,end)` 秒。三段区间是独立用例，不拼接成一次有状态回放。来源为用户指定的 `/Users/mazhehua/Desktop/乌兰察布测试数据/叠框视频_20261010`；原参考用例另行保留。
- 将控制器截止规则与帧选择区间分离。按已解析的片段长度和单独的准备、收尾预算确定截止时间，替代所有用例共用的 120 秒常量。超时仍是不完整运行，不能当作完成指定区间。

用户于 2026-10-16 明确调整本次续跑验收范围：跳过 `test-02-20260929-1605.叠框.mp4`，仅对 test-03 的三个区间各执行三轮参考和三轮候选，共 18 轮。准备预算在新参考运行前固定为 P=3600 秒，收尾预算仍为 C=10 秒。原四项配置及整段支持继续保留，test-02 标记为用户豁免、未通过本次实测，不再次准备或回放；原 90 秒预算失败和单独内存诊断记录原样保留，不混入新的比较组。

例如，过去需要用固定输入和多组命令行参数反复运行。变更后，一份配置可以列出录像 A 的 `[55,75)` 和录像 B 的全部帧；工具依次准备两个用例，逐项运行并生成独立比较及汇总。

## Capabilities

### New Capabilities

无。扩展现有回归能力，避免建立职责重复的规格。

### Modified Capabilities

- `rk3576-tracking-regression`：新增单配置多用例入口及串行套件汇总；把固定用例、时序、完整性、准备、基线和截止时间要求推广到可配置区间及整段录像。

## Impact

- 主要修改 `tests/tracking_regression/`：新增配置解析和套件调度组件，调整 `prepare_fixture.py`、`verify_fixture.py`、`run_batch.py`、`realtime_source.*`、`main.cpp`、`collect.py`、`identity.py`、`metrics.py`、`baseline.py`、`compare.py` 及相应 JSON 结构约束。JSON 结构约束定义记录允许的字段、类型和版本。
- 更新对应 Python/C++ 测试、`CMakeLists.txt`、使用文档及配置示例。构建和 SDK 测试脚本的命令行不属于本次替换范围。
- 新记录使用明确的新版本。旧格式只按旧契约读取；新旧格式不能在缺少比较条件证明时直接混入同一比较集合。旧基线、现场录像、模型和验收记录不被重写。
- 不修改生产跟踪算法、ROS 接口、顺序回放入口或生产视频编码支持范围。不新增模型训练、设备部署或真实飞行验收。
- 真实模型及性能验收仍使用同一块指定生产板和系统 RKNN Runtime 2.3.2、驱动 0.9.8。整段录像的内存需求随帧数增长；资源失败必须保留证据，不能以主机检查替代板端结论。
- 四个新增用例继续交付配置及输入核验。指定数据已迁移至 `/home/mzh/乌兰察布测试数据`，来源和逐帧对应核验见 `onboard-test-report-resumed.md`。本次生产板运行按上述用户豁免只验收三个 test-03 区间；不捏造 test-02 实测通过结论。
