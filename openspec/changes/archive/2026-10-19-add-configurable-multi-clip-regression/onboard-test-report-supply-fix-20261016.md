## 修复与证据

内核将 CPU 4–7 从普通负载均衡中隔离。原先继承的 0–7 允许集合未让供帧线程使用隔离核心。固定 CPU 竞争诊断中，继承方式三轮均超过 50 毫秒，峰值为 121.73–123.12 毫秒；同一二进制仅将供帧线程放到 CPU 4 后，三轮均合格，峰值为 2.30–2.86 毫秒。诊断证明这一调度机制及对应修复，但旧失败没有分段时序，不能声称已经证明它们的唯一原因。

新增可选 `run.settings.supplier_cpu`。该值只控制测试供帧线程，进入比较条件，并在回放时钟前设置及回读。实际线程身份、策略、CPU 集合及设置时刻保存为独立证据。原始帧时间、像素副本所有权、姿态历史、50,000 微秒规则和模型行为保持原值。正式十八轮不运行人工竞争进程或调度采样器。
