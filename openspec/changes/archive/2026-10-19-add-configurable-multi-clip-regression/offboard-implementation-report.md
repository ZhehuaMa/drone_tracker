## 交付范围

- 新增 `configuration.py` 和 `run_suite.py`。公开业务入口只接收一份配置；完整校验先于输出创建和首个用例执行。配置原文、解析后路径及校验值作为本次请求的快照保存，后续操作不重新读取外部配置。
- 新增明确版本的结构约束。套件配置为版本 1，逐轮配置为版本 3；可变输入相关记录为版本 2。旧记录保留固定参考契约的只读校验；新旧轮次或不同用例不能拼为一个正式集合。
- 准备组件按原视频的真实帧时间选择区间、整段或至末尾范围。它核对日志与视频的帧数和时间对应关系、可信尾部、姿态和算法来源。FFV1 无损片段保留原亮度像素和尺寸。准备失败或源内容在解码期间变化时不留下可运行的完整 fixture。fixture 指包含片段、逐帧映射、姿态和校验清单的不可变输入目录。
- C++ 帧源使用本用例的尺寸、帧数和回放长度。每轮仍先全量缓存并验证实际像素，再加载模型，最后建立回放时钟。队列持有像素副本；慢消费不改变录像时钟。没有增加固定缓存上限或流式回退。
- 外部监督记录准备预算 P、回放长度 D、收尾预算 C，以及总截止 `P + ceil(D) + C`。准备超时、控制器挂起和最终化失败都不能产生合格运行。不能确认进程树回收时停止后续计划，并保留未执行轮次。
- 完整性、指标、冻结和比较按独立用例处理。`full` 为该用例的 `[0,D)`；额外窗口必须显式声明。报告保留缺失、不完整、不可比和未设置门槛的状态，分开表示操作成功与性能通过，不跨录像混算指标。
- README、指标文档和示例说明四种操作及迁移边界。四个指定叠框用例的模板已交付；尚未核验的日志、姿态和 session 路径明确为 TODO，不能直接作为正式输入执行。原参考用例另有模板保留。
