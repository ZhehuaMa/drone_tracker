# RKNN 同步完成修复与回归（2026-09-23）

> 本文保留同步修复当时的回归结果。后续独占检查实现、人工画面观察和剩余任务状态见 [最终验收记录](final-validation.md)。文末的未完成项是当时状态。

## 对象与问题

验收对象为 `firefly-production` 对应的生产 `HZ-RK3576_WuKong Board`，主机名 `hzhy`、内核 `6.1.141-rt36`。使用系统 RKNN Runtime 2.3.2、RKNPU 驱动 0.9.8。未升级 SDK，也未替换系统库。

原问题是 Search Backbone（NanoTrack 搜索图像的特征提取模型）共享输出路径在同步 `rknn_run` 成功后调用 `rknn_wait`。Runtime 没有为此路径提供有效 fence，即设备完成通知凭据，因此等待失败并触发资源保护退出。历史证据见 [隔离诊断](isolation-diagnosis.md)。

## 同步契约与适用范围

核对 Rockchip 官方固定版本资料：

- [Runtime 2.3.2 接口手册](https://raw.githubusercontent.com/airockchip/rknn-toolkit2/v2.3.2/doc/04_Rockchip_RKNPU_API_Reference_RKNNRT_V2.3.2_EN.pdf)，第 16 页区分阻塞与非阻塞运行；第 30 页要求当前 `rknn_run` 扩展参数使用 NULL。
- [2.3.2 头文件](https://raw.githubusercontent.com/airockchip/rknn-toolkit2/v2.3.2/rknpu2/runtime/Linux/librknn_api/include/rknn_api.h)，区分异步初始化、fence 输出和禁用输出缓存同步等标志。

本项目会话固定初始化标志为 0，执行参数为 `nullptr`，没有开启异步或禁用输出缓存同步。结合以下实机输出对照，确认此路径成功返回后可使用本次输出，不需要额外等待。此结论不推广到非阻塞执行、异步初始化或自行禁用缓存同步的路径，也不表示执行失败已经停止。

## 独立最小验证

探针源码见 [sync_probe.cpp](evidence/rknn-sync-20260923/sync_probe.cpp)。不加载 OSD，不打开显示设备。固定 FP16 Search Backbone 指纹为 `9ca8cc19dd0de798a3075c0f797ad4508362d9c297f9a1f04e784c34bfdc9f44`。

测试创建两个模型会话。参考会话使用普通输出获取；另一会话保持生产代码的“提交输入 → 绑定 FP16 NC1HWC2 原生共享输出 → 同步运行”顺序。NC1HWC2 是设备把通道分组保存的布局，探针按实际行跨度还原后逐元素比较。共享会话不调用 `rknn_outputs_get`、`rknn_wait` 或额外缓存同步。

连续交替两个不同输入共 100 轮。所有轮次最大绝对误差为 0；两个输入的输出最大差为 6.60546875，排除了始终读到相同旧数据。重复输入 A 的输出完全一致。每次返回后另等 2 ms，再比较整块内存，100 次均不变。最后正常释放共享内存和两个上下文。

## 修改与自动化验证

`RknnSession::run()` 仅在同步成功时将 `running_` 清为 false。失败路径继续要求完成确认；确认失败仍终止进程，避免设备继续访问已释放的输入或共享内存。成功后输出取回失败仍返回错误并使会话失效，但不再等待不存在的 fence。

新增或调整模拟断言：同步成功但 wait 将失败、连续共享推理、Search 到 Head 共享交接、同步成功后取回失败、run 超时/失败且 wait 失败、共享资源释放失败。模拟 SDK 同时验证初始化标志为 0、运行扩展参数为空。

- 约定 ARM64 容器 `./build.sh --test`：34/34 通过。该构建默认关闭 OSD，SDK 头库环境为既有 2.3.0，不替代生产板证据。
- 生产板直接相关测试：`rknn_session_tests`、`rknn_runtime_tests`、`rknn_nanotrack_backend_tests`，3/3 通过。
- 静态检查缺口：仓库没有配置目标平台 clang-tidy/clangd 命令，约定容器不提供这两个工具。本机虽存在工具，但其本机环境不能代替 ARM64 SDK 检查。执行编译、相关测试和 `git diff --check`。

## 最终结果

最终节点可选消息适配为 OFF，SHA-256 为 `74425b92f2458cd38e6c1df603f8c8f60fc8e608a26438b976f42230f8417772`。以下各阶段顺序执行，使用相同模型与视频，没有与其他模型探针并发。

| 阶段 | 有效运行 | 跟踪输出 | 结果 |
|---|---:|---:|---|
| OSD 关闭 | 40.0756 秒 | 800，约 19.96 次/秒 | 正常停止，退出码 0 |
| 独占 HDMI 短测 | 30.0531 秒 | 603，约 20.06 次/秒 | 无显示停用，退出码 0 |
| 同进程启停 | 前 20 轮，每轮至少 2 秒 | 每轮重新开始并在 OFF 后停止 | 同一 PID 14999，未发现上一轮时间戳回流 |
| 同进程额外长轮 | 第 21 轮，610.2008 秒 | 12,165，约 19.94 次/秒 | 无 RKNN 等待失败、DRM 错误或显示停用，退出码 0 |
| 显示故障注入 | 10.1252 秒 | 204 | 显示停用后业务继续，退出码 0 |

21 轮最大停止确认耗时为 331.6 ms，第 21 轮为 305.7 ms。它从发送 OFF 到验收端收到停止消息计时，包含消息传输和调度，不是 HDMI 冻结像素出现时间。长测进程最终退出耗时为 516.6 ms。

长测最后一次周期日志为 `submitted=13057 replaced=0 displayed=13044 commits=13333 rejected=0`。这些是截至最后一次采样的累计值，不是精确的退出瞬间计数；停止可能丢弃尚未显示的完整包。长轮周期日志区间约 610.91 秒，新画面显示约 19.89 次/秒，提交完成约 19.94 次/秒。HDMI 配置模式为 720×480、60 Hz；提交完成频率不是物理屏幕扫描频率，未独立测量扫描频率。

### 资源与性能边界

- 前 20 轮停止后的线程数全部为 17，文件描述符全部为 49，没有逐轮增加。
- 长轮运行时为 19 个线程。文件描述符在约 68.31 秒从 50 增到 56，此后一直保持 56；停止后为 55。观察到一次台阶后稳定，尚未对新增的六个句柄逐一归因，不能写成“所有资源均回到首次基线”。
- 长轮 RSS（进程实际驻留内存）范围为 124,220–144,592 KiB。300 秒之后范围为 134,204–144,592 KiB，结束停止后为 134,692 KiB。采样未显示持续无界增长；没有测量 NPU 设备内存。
- 按进程 CPU 累计时间除以墙钟时间估算，OSD 关闭约占一个 CPU 核的 98.2%，HDMI 短测约 120.8%，长轮约 127.4%。统计窗口包括末尾停止与约一秒空闲期，不能视为精密性能基准。固定 20 FPS 输入下，两种配置都接近输入速率，不代表最大吞吐没有差异。
- 未测进程内提交耗时分布、相机曝光到屏幕的端到端延迟或屏幕实际像素。额外负载不替代这些缺失项。

合成场景长轮出现 511 个被算法标为有效的框，但没有无人机真实标注。仅报告接口行为，不评价检测正确率、目标跟踪质量或屏幕运动框配对。
