# Design

## Context

当前屏幕不绘制经纬度，解锁文字也会在短暂闪烁后消失。目标是在既有视频叠加层中补充右侧坐标和底部持续解锁状态，且不让触发提示遮住状态。用户可见动机见 [proposal.md](proposal.md)。

OSD 指叠加在视频上的信息；HUD 指其中独立于目标框的遥测和状态图形。代码检查确认：

- `src/osd/ros_telemetry.cpp` 已订阅位置和飞行状态。`TelemetryStore` 是验证遥测并生成独立快照的数据容器；`TelemetrySnapshot.position` 已提供经纬度，`flight` 已提供连接与解锁状态。
- 位置接收逻辑已拒绝无定位、非有限和越界坐标。快照按单调时钟移除过期位置及飞行状态，默认期限为 2000 毫秒。此时不应由绘制层保留旧数值。
- `src/osd/layout.cpp` 用统一元素定义驱动两条路径：`legacy` 每次完整绘制，`cached-overlay` 保存上次图形并只重画变化区域。两者复用同一 720×480 逻辑画布。
- `MAH` 行当前起点为 `(554,276)`。主字形为 16×32 像素，文字框额外包含 4 像素描边空间。
- 解锁状态与触发提示当前共享底部位置，且使用互斥分支。`ARMED` 还有解锁后三秒及 300 毫秒闪烁条件。`src/osd/presenter.cpp` 管理触发提示的既有两秒期限。
- 现有主规格已要求有效位置用于经纬度显示，但尚未定义格式和布局，当前布局也没有绘制该字段。本变更补足该缺口。
- `rk3576-hdmi-osd` 的固定参考布局和目标框要求含有“其他 OSD 项目保持不变”的约束。本变更通过完整的 MODIFIED requirement 明确坐标、解锁状态和触发位置三类例外，不将其视为隐含授权。

[参考图](reference/osd-gps-armed-mockup.png)保存的是生成的 1536×1024 示意图。其用途是说明分区、顺序和颜色，不是精确字形或坐标基准，也不是运行证据。六位小数与主字号要求优先于示意图的像素细节。

## Goals / Non-Goals

**Goals:**

- 复用现有快照和统一绘制元素，保证两条路径一致。
- 给最长合法坐标和 `DISARMED` 留出完整空间。
- 在无框预览、跟踪、等待和冻结状态中持续反映新鲜遥测。
- 为无定位、断连和超时提供明确占位文字。

**Non-Goals:**

- 不新增位置或飞行状态订阅，不改变消息、QoS（消息交付策略）或超时参数。
- 不修改解锁计时、返航点、跟踪状态、相机启停、模型和设备缓冲管理。
- 不实现目标框动态避让 HUD，不改变既有目标层与 HUD 的叠加顺序。
- 本次规划不执行代码修改、构建或生产部署。

## Decisions

### 1. 从现有有效快照生成文字

选择：在 `src/osd/short_text.*` 增加坐标格式化入口，并从现有 `position`、`flight` 快照生成文字。格式化坐标时再次防御性检查有限性和地理范围。六位小数使用固定精度，显式符号和英文小数点；使用固定数字区域设置，避免运行环境把小数点改为逗号。四舍五入后为零的坐标统一为 `+0.000000`，不显示负零。

理由：已有接收和过期规则足够，不需要第二套数据生命周期。文字转换可单独验证，显示精度也不会被误认为定位精度。

替代方案：从 GPSRAW 的整数位置重新计算坐标，或在绘制时缓存最后坐标。前者引入重复来源，后者会绕过超时规则，因此不采用。

结果：位置无效时统一输出 `LAT --`、`LON --`。有效零坐标仍正常显示，坐标可在未解锁且没有返航点时显示。

输入到屏幕的过程：

1. 现有位置订阅接收 `(31.2304,121.4737)` 并验证定位状态和范围。
2. 现有 10 Hz 遥测汇总生成仍含有效 `position` 的快照。
3. 格式化得到 `LAT +31.230400`、`LON +121.473700`，统一元素分别绘制在右侧两行。
4. 超时或收到非法位置后，下一份快照没有有效位置，两行改为占位文字并清掉旧数字。

### 2. 用固定主字号和右对齐容纳坐标

选择：沿用 `MAH` 的 16×32 主字体、白色和黑描边。以 720×480 逻辑画布确定下表位置。其他输出尺寸沿用现有整体缩放。

| 元素 | 逻辑位置与范围 | 原因 |
|---|---|---|
| `MAH` | 保留 `(554,276)` | 不移动既有电池列 |
| 纬度 | 顶部 `y=314`；文字框右边界 `x=702`，边界不包含该列 | 紧接电池数据下方，完整容纳主字形及描边 |
| 经度 | 顶部 `y=350`；同样右对齐到 `x=702` | 36 像素文字框在 `y=386` 前结束，避开冻结提示 |
| 解锁状态 | 顶部 `y=430`；文字框中心为 `x=360` | 对齐参考图底部中央，并容纳较长的 `DISARMED` |
| 触发提示 | `(22,80)` | 位于副标题与高度行之间，不占用底部状态位置 |

文字框宽度按 `字符数×16+4` 计算，包含描边；右对齐起点为 `702-文字框宽度`。例如 `LON -180.000000` 有 15 个字符，框宽 244 像素，起点为 `x=458`。这使负号、三位整数和六位小数都能保留。纬度行在 `y=350` 前结束，经度行在 `y=386` 前结束，冻结提示仍从原有 `y=386` 区域绘制。

理由：坐标无法从原电池列的左边界开始绘制而保持完整主字号。向左扩展并右对齐可满足阅读要求，无需缩小或截断。

替代方案：在左侧放小字、删减小数或右列左对齐后裁切。这些都不满足用户明确的字体和位置要求，因此不采用。

结果：只新增坐标并迁移触发文字；时钟、告警、冻结提示、跟踪阶段、任务状态与目标框继续使用现有分区。最长经度从 `x=458` 开始，与现有跟踪阶段提示右边界之间仍有间隔。

### 3. 让解锁文字成为独立的持续元素

选择：根据当前快照每次生成一个独立解锁元素。新鲜且已连接的状态映射如下：`armed=true` 为绿色 `ARMED`，`armed=false` 为白色 `DISARMED`；没有状态或 `connected=false` 时为琥珀色 `ARM --`。移除现有三秒及闪烁条件，解锁元素与触发元素分别生成，不再互斥。

理由：用户需要在任意时刻查看当前解锁状态。新鲜的断连消息也不能确认飞行控制器此刻是否已解锁；固定未知文字比默认上锁更准确。该判断只用于显示，不影响现有飞行状态存储、计时和返航点逻辑。

替代方案：延长闪烁时间，或把 `ARMED` 与 `TRIG ON/OFF` 轮流显示。这些方案仍留下看不到解锁状态的时间段，因此不采用。

结果：解锁 75 秒时仍显示 `ARMED`。`OFF` 只代表跟踪关闭，不改变解锁文字；状态消息报告上锁后才改为 `DISARMED`。未知数据不能继续断言先前的解锁状态。

### 4. 复用变化区域缓存并保留其他显示契约

选择：为纬度、经度和持续解锁状态建立稳定的独立元素标识。元素内容或颜色变化时，沿用缓存绘制器对旧范围和新范围的清理。触发提示仍由现有显示控制器决定是否到期；这里只改变它的位置。

理由：统一元素可保持两条路径输出相同，并在 `DISARMED` 变短为 `ARMED`、坐标变为占位文字时清除旧后缀。稳定状态不应因时间经过而重画这些元素。

替代方案：为两条渲染路径各写一套坐标和解锁绘制，或额外增加显示线程。这会增加不一致与资源管理风险，因此不采用。

结果：无需修改 HDMI 后端或帧提交生命周期。新增 HUD 与既有目标框发生几何交叠时，继续遵循原有目标层顺序，不引入目标框移动、裁切或避让算法。

## Risks / Trade-offs

- 最长经度容易被右边缘裁切 → 使用包含描边的右对齐计算，覆盖南纬、西经、边界值及宽画布快照。
- 下方空间有限 → 固定坐标行在冻结提示之前结束，独立迁移触发文字；验证告警、冻结、任务覆盖和跟踪启动组合。
- 缓存路径可能留下旧字符 → 验证长短状态切换、坐标未知与恢复，并逐像素比较两条路径。
- 生成示意图与真实字形存在差异 → 保留示意图作为视觉意图，后续以真实绘制器生成快照并记录输入、字体和精确范围。
- 主机测试不能证明生产 HDMI 可读性或负载表现 → 软件快照与板端记录分开。生产板不可用时，相关任务保持未完成，不以模拟图作为实机通过证据。

## Migration Plan

1. 后续 apply 阶段先实现格式化与统一布局，再运行现有 OSD 定向测试，生成可重现示例图。
2. 在独立缓存中使用 `./build.sh --test` 完成 ARM64 目标构建与测试，并记录实际构建镜像和测试平台。原生 x86_64 OSD 检查按 `dockerfiles/README.amd64.md` 的独立入口运行。
3. 用户后续要求部署时，按既有生产部署流程保留原版本，在 `HZ-RK3576_WuKong Board` 上确认文字可读、未知状态、触发共存及原有显示性能要求。记录板卡、程序、配置、模型指纹、输入和显示模式。此计划不自动授权生产部署。
4. 回退使用原有程序版本；消息、模型及参数没有新增项，因此无需数据或配置迁移。
