- [x] 1.1 建立 Detecting 的结果快照、当前提交、旧结果处置顺序，修改 `src/hybrid_tracker/hybrid_tracker.cpp` 的未初始化路径。完成条件是正常交互点只调用一次 `get_result()`，先保存结果，再尝试当前请求，最后按保存标志进入原处理代码；既有输入及时间早退不新增读取。
- [x] 1.2 证明 Detecting 的接收及结果身份，在 `src/hybrid_tracker/tests/diagnostic_tracker_test.cpp` 增加已就绪正结果、负结果及空快照用例。完成条件是受控就绪结果在新提交前取走，旧结果不丢失、只处置一次，当前请求和旧结果各保留来源身份；无结果时不等待推理，原 `testUnreadResultAdmission()` 不被削弱。
- [x] 1.3 建立 Tracking 的同一顺序，修改 `hybrid_tracker.cpp` 已初始化路径。完成条件是当前 NanoTrack 观测及来源快照先建立，再读取一次结果，执行原间隔提交或跳过，最后处理保存结果；保持原无结果计数及严格看门狗公式。
- [x] 1.4 证明 Tracking 的节奏及状态边界，在 `diagnostic_tracker_test.cpp` 增加提交帧、非提交帧、来源元数据、重复时间及原生跟踪跳变早退用例。完成条件是非提交帧仍读结果且不额外请求，早退不读结果，旧回合与来源图像缺失仍按原规则处理，看门狗临界值和未确认计数测试通过。
- [x] 1.5 说明新的结果快照边界，在两个交互点附近添加简洁的英文源码注释。完成条件是注释能独立解释为何先读取、为何先提交再补跟踪、为何不进行第二次读取；不声明保证命中特定帧或消除所有未读拒收。
