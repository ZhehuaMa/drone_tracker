# 启动预热实施任务

本清单按实现和验证证据更新；详细结果见 [validation.md](validation.md)。固定规则见 [design.md](design.md) 和两份规格增量。本变更先于 `add-rk3576-camera-recording` 集成，不依赖录像实现。

## 1. 预热判断与时间边界

- [x] 1.1 提供有界观察状态，在 `src/platform/rk3576/` 的相机时间模块实现固定 2 秒、120 帧、连续 8 帧规则；完成条件是重复计数重置为 1、第 8 帧可输出、第 120 帧边界和到期优先行为符合规格。
- [x] 1.2 保留严格时间输出，在 `camera_timing.*` 周边分离观察校验与正式输出状态；完成条件是固定偏移不重采样、首观察帧锁定策略、非法时间/倒退/溢出失败、既有未知时钟回退不变。
- [x] 1.3 验证纯时间规则，扩展 `tests/camera_timing_test.cpp` 或相邻专用测试，覆盖实测重复模式、全重复、间歇出队、恰好到期、最后允许样本成功、时间策略切换及正常阶段再重复；断言时间值未人工修改。

## 2. 采集线程与资源生命周期

- [x] 2.1 区分采集结果，在 `rk3576_camera_capture_base.*` 增加无样本、预热丢弃和合格帧结果；完成条件是预热成功出队保留元数据且不会被上层误判无帧。
- [x] 2.2 只为 SC233HGS 启用预热，在 SC233HGS 设备和共用采集基类完成型号策略；完成条件是预热前不复制灰度或调用录像分流，AR0234 仍从原首帧开始检查。
- [x] 2.3 保证缓冲及序号处理完整，在共用采集边界校验全部成功出队序号并归还观察帧；完成条件是重复/倒退序号失败、自然回绕和向前缺口按原规则处理、归还失败不继续采集。
- [x] 2.4 保持异步启动和可中断等待，在 `ar0234_camera_frame_source.*` 接入结果分类、绝对期限和停止唤醒；完成条件是无帧/EINTR/EAGAIN 不续期，OFF 不等待稳定，新轮清除旧观察状态。
- [x] 2.5 验证共享资源边界，扩展 SC233HGS 及 AR0234 设备/帧源测试，覆盖预热中停止、归还失败、序号错误、部分初始化失败和重复重启；完成条件是无重复归还、泄漏、旧帧混入或 AR0234 行为回归。

## 3. 诊断与 ROS 行为

- [x] 3.1 提供完整对账字段，在平台普通状态数据和相机诊断结构加入出队总量、预热计数、终止处置及首帧身份；完成条件是成功、失败、取消三类终态均满足设计中的互斥计数关系。
- [x] 3.2 保存有限原始证据，在相机诊断和独立采集验收工具中导出最多 120 条预热元数据；完成条件是包含时间、标志、序号、出队时刻和判断，且不保留像素或逐帧阻塞写盘。
- [x] 3.3 呈现首帧与失败原因，在 `src/drone_tracker_node.*` 日志中报告预热汇总；完成条件是未知首帧不显示零延迟、常规统计每秒最多一次、业务话题和 TrackerState 数值不变。
- [x] 3.4 验证跨层启停，在相机/ROS 受控测试覆盖预热帧不进入算法或框/图像发布、预热中 OFF、失败后 ON、正常阶段重复失败；完成条件是没有伪造 TargetLost 或模型重新加载要求。

## 4. 构建与生产板验收

- [x] 4.1 完成匹配的 ARM64 构建和相关测试，按 `AGENTS.local.md` 使用现有 `build.sh --test`；交付测试结果，注明缺 SDK、静态检查或 Jetson 实机环境等未执行项。
- [x] 4.2 完成生产板 20 轮独立启停及 100 次新建销毁，使用公共帧源验收入口；交付每轮预热记录、首帧延迟分布、计数与相机停止耗时，真实相机停止不超过 1 秒。
- [x] 4.3 完成生产板至少 20 分钟持续采集并包含慢消费者，交付时间递增、队列丢弃、内存/线程/文件描述符趋势及退出后设备占用证据；异常或持续资源增长标记未通过。
- [x] 4.4 完成正式模型下 ROS 首帧与启停回归，在生产板记录代码/模型/输入身份、OFF、失败恢复、话题和状态结果；目标未捕获单独报告，不把输入修复等同于模型质量通过。
