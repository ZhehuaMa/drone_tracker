# 移除 OSD 目标标签的设计

## Context

当前目标框旁的文字面板会遮挡视频及附近的遥测。预期效果是移除整块面板，并保留目标角框、锁定装饰和独立状态栏。动机及外部行为见 [proposal.md](proposal.md)。

OSD 表示视频上的屏幕信息叠加；HUD 表示独立于目标框的飞行、状态和告警信息。`src/osd/layout.cpp` 中的 `addTarget()` 生成目标图形，`scene()` 组合其他 HUD 元素。`legacy` 与 `cached-overlay` 是现有两条渲染路径，均使用同一组元素定义。前者重新生成图层，后者复用图形并局部重画。

当前目标元素同时包含角框、锁定外角框、中心菱形和标签面板。标签文本参与缓存标识；标签底板与目标框的联合区域参与绘制范围计算。缓存标识是用于判断元素是否需要重画的内容摘要。局部重画区域包含旧元素和新元素占用的范围，用于清除移动后残留的图形。

`targetLabelText()` 还向 `src/osd/presenter.cpp` 的显示提交日志提供可见标签文字。现有 `presenter_test.cpp` 将非空标签视为预期诊断。因此本变更需要同时明确绘制、缓存和日志的语义，满足设计文档的编写条件。

## Goals / Non-Goals

**Goals:**

- 将修改限定在公共 OSD 布局、可见文字诊断及其针对性检查中，让两条路径自然得到一致输出。
- 保留目标框几何和各状态的颜色、线宽、锁定装饰，不调整其他 HUD 元素。
- 保留输入数据结构和日志字段格式，避免为一个显示删减改动上游跟踪结果。

**Non-Goals:**

- 不新增标签显示参数或运行期开关。
- 不改变 ROS 调试图像绘制、状态机、模型、相机、线程、设备缓冲区或 HDMI 后端链路。
- 不部署程序，不安排长时间稳定性测试或性能测试；本次功能回归不重新执行历史优化变更的持续负载验收。

## Decisions

### 1. 从公共目标元素中移除整个标签面板

**选择：** 在 `addTarget()` 中去掉标签生成、底板几何及文字、底色、边框绘制。保留原来的角框与锁定装饰代码。目标元素绘制范围改为目标框加既有 8 像素外扩，再裁剪到视频与画布；该范围仍覆盖向外延伸 6 像素的锁定角框。缓存标识只保留目标几何和状态，不再含输入标签。

**原因：** 两条渲染路径共享这段定义，集中删除可保证效果一致。只把文字置空仍可能生成空底板，不能满足移除整块面板的要求。

**未采用方案：** 不在 HDMI 合成后涂黑标签区域，不分别修改两个后端分支，也不另加标签开关。涂黑会遮住底层内容；分支修改容易产生差异；开关不属于用户要求。

**结果：** 面板原来遮住的底图、遥测或角框自然显露。缓存中的目标移动和清除仍沿用既有局部重画机制，且输入标签变化不影响目标像素。

### 2. 保留输入字段和诊断格式，但可见标签始终为空

**选择：** 保留 `DisplayBox::label` 输入字段。保留 `targetLabelText()` 的声明及日志使用方式，将其返回值统一改为空字符串，并更新 `layout.h` 的说明。显示提交日志继续输出 `target_label=""`。独立状态文字继续由 `statusBarText()` 按现有跟踪状态或任务覆盖生成。

**原因：** 日志描述实际画面，不能把未绘制的文字记录成已显示标签。保留字段格式能避免不必要的诊断解析兼容性变化。

**未采用方案：** 不删除上游输入字段和整套日志字段，也不继续返回输入标签或跟踪状态。前者扩大修改范围；后者使诊断与画面不符。

**结果：** 非空目标名称与空标签都得到相同目标图形。右上角 `TRK TRACKING`、`ON MISSION`、触发日志及状态切换日志保持现有规则。仅输入标签改变不会新增显示切换日志。

### 3. 用固定输入验证显示差异和短时功能行为

**选择：** 复用 `osd_layout_tests`、`osd_hud_style_tests` 和 `osd_presenter_tests`。前两者检查图形和两条路径一致性，后者通过模拟显示后端检查状态、任务与日志。采用固定遥测、框、画布尺寸和绘制时刻，避免时钟及闪烁造成无关差异。

**原因：** 变更只删除显示元素，没有修改硬件处理或算法负载。确定性像素对照和现有短时模拟检查能直接验证此次外部行为。

**未采用方案：** 不添加持续负载、长时间启停、吞吐量、帧率、延迟或 CPU 占用测试，也不以这些测试作为本变更完成门槛。

**结果：** 验证记录只声明本次视觉与功能回归结果，不宣称新版本已经完成生产板性能或长期稳定性验收。既有主规格中的其他验收条款不作删除。

像素对照按以下顺序进行：

1. 使用原实现固定输入生成 HUD 和目标层，保存到本次独立产物目录。
2. 使用新实现与完全相同输入生成对应图层，并合成到同一底图。
3. 比较 HUD 图层和目标几何，确认标签原覆盖区域外的像素一致。
4. 对原覆盖区域检查底层内容恢复；不能简单要求全部透明，因为标签曾遮住锁定外角框或其他图形。

例如，空标签输入原先回退显示 `TRK TRACKING` 面板。新实现不生成面板，右上角仍显示 `TRK TRACKING`，绿色目标角框及中心菱形不变。

## Risks / Trade-offs

- **只移除文字却遗留空底板** → 同时检查文字、底色和边框；覆盖非空、空标签及长标签输入。
- **缩小绘制范围裁掉锁定外角框** → 保持现有外扩规则，检查靠近视频边缘的小框和两种画布尺寸。
- **局部重画留下旧框残影或覆盖相邻遥测** → 比较框移动、清框和冻结后的缓存输出与完整重绘输出。
- **日志仍声称标签可见** → 更新可见文字辅助函数与日志断言，覆盖任务触发、标签变化和停止。
- **对比快照被误认为实机结果** → 在记录中注明构建平台及软件快照来源；不把软件快照称为 HDMI 实机验收。

## Migration Plan

本变更没有参数或数据迁移。实施阶段先保存原实现固定输入快照，再修改公共布局与诊断辅助函数，最后完成针对性回归并记录结果。历史归档图保持原样，新对比图保存到本次验证产物目录。此次不安排生产部署；日后如需回退，只需恢复本变更涉及的布局和诊断实现，无需修改运行配置。
