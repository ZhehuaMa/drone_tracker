# Design

## Context

当前左下条形表示剩余电量，温度行占用其上方空间。目标是在相同分区显示遥控接收链路强度，同时避免把旧电量数值误当成无线信号。动机见 `proposal.md`。RSSI 在此采用飞控提供的 0–100 链路质量百分数；它可能来自接收机 RSSI 或 CRSF LQ，不代表 dBm 接收功率或视频链路质量。

权威输入来源是本机 `/home/mzh/nickluo/apm_bridge` 的 `rk3576` 分支，核对提交 `390668d2d822731e95651cd3b88547e5912e66a1`。`include/custom_link/protocol.h` 的 `PayloadMedium.rssi_pct` 定义 0–100；`src/custom_link_vehicle_node.cpp` 的 `handleMedium` 原样赋给 `mavros_msgs/msg/RCIn.rssi`；发布话题为 `/mavros/rc/in`，best-effort，深度 10。`README.md` 同样记录这一百分比契约。本地 `rk3576` 无上游配置；只读 `git ls-remote origin refs/heads/rk3576` 未返回同名远端分支，因此此处的“最新”指用户指定的本地分支当前提交，不声称已同步不存在的远端分支。生产板现有桥接服务不是该最新源码，因此仅用于确认接口和运行环境，不能代替上述来源。

生产板只读发现：主机 `hzhy`、ARM64，`drone-tracker.service` 与 `drone-interceptor.service` 均在运行；`/mavros/rc/in` 的现有发布者为 `custom_link_bridge`。限时观察没有取得 RSSI 样本，这不证明真实无线链路可用，也不阻碍用隔离话题验证显示。规划阶段没有停止服务。

## Goals / Non-Goals

**Goals:**

- 在现有显示侧快照增加独立有效性的 RSSI 百分数，不把 ROS 类型扩散到绘图层。
- 保持温度接收和电池解析兼容，只替换可见温度和电量条用途。
- 两条显示路径共享元素定义，保持缓存刷新和未知值清除语义。

**Non-Goals:**

- 不修改桥接仓库、固件、遥控触发、跟踪算法、采集或推理模型。
- 不增加通用 RSSI 标度自动检测，不支持把任意 MAVLink 0–254 原始数直接当作本项目输入。
- 不新增弱信号告警、不修改现有告警优先级、不永久更新生产安装。

## Decisions

### 1. 采用最新桥接源码的直接百分比

**选择：** `RCIn.rssi` 为 0–100 时原样保留；101–255 立即清空显示侧有效值。有效 0 与未知分开。订阅使用 best-effort 深度 10，并保留 ROS 话题重映射能力。

**原因：** 最新 `rk3576` 源码已把字段定义为百分比。85 按 254 换算会错误显示约 33%。

**未采用：** 根据数值自动猜测 0–100 或 0–254，或改用未使用的 `RadioStatus` 输入。两种标度在 0–100 区间重叠，无法可靠猜测；替换输入还会失去已确认的生产来源。

**后果：** 文档必须说明适用的桥接契约。其他发布者需要先转换到 0–100，本变更不隐式转换。

### 2. 保持显示侧独立所有权和单调时间

**选择：** 在 `TelemetrySnapshot` 增加 `Measurement<int>` 百分数字段；`TelemetryStore` 的现有互斥锁保护接收和快照。复制快照后按自身时间戳过期，复用 `osd.telemetry_timeout_ms` 与 10 Hz 汇总。

**原因：** 单调时钟衡量已经过的时间，不受系统校时影响。独立时间戳使电池更新不能维持旧 RSSI。

**未采用：** 从 ROS 消息持有借用数据，或以图像/电池接收时间代替 RSSI 时间。

**后果：** 没有新线程、队列或硬件资源。RSSI 在预览和冻结阶段仍通过原有快照通路更新。温度字段和电池比例可保留，避免扩大数据接口变更。

例：

1. ROS 接收有效 `rssi=85`，记录单调时间。
2. 下一次快照带独立有效百分数 85。
3. 共享布局把百分数转换为 125 像素黄色填充与 `85%`。
4. 超过 2000 毫秒无新输入，下一次快照令 RSSI 未知；布局清填充并显示 `--%`。

### 3. 原位替换显示元素

**选择：** 删除 `temperature` 绘制元素。在逻辑 `(22,278)` 使用既有主字体绘制 `RSSI`。把原 `battery-bar` 元素替换为含轨道、填充和唯一百分数的 RSSI 元素。轨道 `(20,330,150,12)`、填充起点 `(21,331)`、内部 148×10、数字起点 `(178,318)` 保持。条长使用整数 `148*p/100` 向下取整。

**原因：** 这与最终确认示意图的分区一致，并保留原条形几何。标签用主字体可与高度、卫星等主字段一致辨认。

**未采用：** 仅把 `TMP` 字符串改成 `RSSI` 并保留温度数字，或新增第二份 RSSI 百分数。两者都会误导操作者。

**后果：** 0% 保留空轨道；未知保留标签、空轨道和 `--%`。有效填充始终为既有黄色，不沿用低电量变红条件。布局仍对畸形直接快照防御性拒绝超范围值。电池告警颜色只作用原电池显示和告警区域。

### 4. 以局部像素和真实订阅验证改义

**选择：** 扩展现有遥测单测、ROS 集成测试和 HUD 测试。用不同电量与 RSSI 证明来源独立，用 0/10/85/100/未知证明边界和颜色，用 100→未知→9 证明旧数字与条形清除。相同输入比较 `legacy` 与 `cached-overlay`，覆盖 720×480 与 1280×720、预览和冻结。

**原因：** 这项变更的风险在数据含义、未知值和缓存残影；完整重跑历史硬件负载矩阵不能替代这些定向验证。

**未采用：** 只验证能编译，或把之前的示意图称为运行截图。

**后果：** 执行 `./build.sh --test`，保存实际输出快照。生产板运行同一候选程序，以独立 ROS 域或输入重映射注入 RSSI，避免把测试数据发给其他生产订阅者。至少观察一次真实相机预览及有效→未知→恢复的 HDMI 图层读回，并以一次有界 ON/OFF 冒烟检查既有跟踪启停。记录模型和输入身份，不把合成 RSSI 称为真实射频测量。

## Risks / Trade-offs

- **输入量纲混淆** → 以最新桥接提交为依据；文档明示直接百分比，测试 85 不应变成 33。
- **过期后残影或假零** → 独立时间戳、未知占位和两路径像素比较。
- **旧基准仍要求电量条** → 更新本 change 的相关完整 requirement，保留其其他场景，主规格不在实施阶段直接改写。
- **候选测试影响生产服务** → 先记录服务、版本链接与配置指纹；停止前准备清理和恢复流程；退出任何路径均恢复原服务，并验证 active/running。不能只记录“已请求启动”。
- **无法取得真实无线遥测** → 真实来源契约由最新源码确认，板端用明确标注的注入值验证显示；不宣称已验证真实射频精度或实飞。

## Migration Plan

1. 在专用工作树构建候选产物和测试，不切换主工作区或其他仓库。
2. 保存生产板的服务状态、当前版本、配置和系统 Runtime 指纹。使用临时候选目录，不覆盖 `/opt/drone_tracker/current` 或系统库。
3. 必要时停止 `drone-tracker.service`，释放显示资源后运行候选版本，保持桌面关闭；其他服务不改动。
4. 结束候选程序并确认资源释放，重启原 `drone-tracker.service`。核对 active/running、进程以及原版本/配置指纹恢复，保存证据。
5. 任何验证失败都停止后续任务；仍执行恢复。此变更不自动归档、不提交、不发布。
