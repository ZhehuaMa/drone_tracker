## Context

RK3576 目前缺少持续跟踪已选目标的模型后端。本次让现有公共跟踪器在独立入口中运行，并允许替换契约相同的模型；动机见 proposal.md。

现有 `NanoTrackBackend` 已定义建立模板、搜索与重置。`NanoTracker` 负责框更新，`nanoPrediction()` 校验分类与位置输出。`RknnRuntime` 则同时负责 SDK 调用和 YOLO 专属限制：一个输入、六个输出、640×640 图像及指定量化参数。不能把它原样用于双输入的 NanoTrack Head。

Backbone 是图像特征提取模型，Head 是比较模板与搜索特征的模型。开发板已有将 Backbone 按 127 和 255 两种输入尺寸拆分的 RKNN 文件。已有彩色评估使用 uint8 图像块；本仓库使用灰度复制三通道，且先转浮点再缩放。因此既有精度报告只用于选择验证起点，不能作为本次实现验收。

## Goals / Non-Goals

**Goals:**

- 固定模型语义契约，允许兼容文件替换；把数据类型差异限制在 RKNN 平台内部。
- 提取一个模型的通用执行能力，同时保留 YOLO 现有拒绝条件、异步调用方停止顺序与输出结果。
- 接通真实公共 NanoTracker，具备可重复的契约查询、固定输入检查与灰度回放。

**Non-Goals:**

- 不实现任意网络、任意张量类型或动态形状的通用推理框架。首版 NanoTrack 使用三个固定形状文件。
- 不更改公共模型接口、跟踪公式、阈值、ROS 参数、平台选择或采集链路。
- 不实现原生量化字节直传、零拷贝、热替换模型或并行访问同一个执行会话。模型替换在重新创建后端时生效。

## Decisions

### 1. 按语义契约接受模型，不冻结模型身份

选择：三个独立路径指定模板 Backbone、搜索 Backbone、Head；无哈希、文件名、训练版本或来源白名单。哈希仅写入验证记录。拒绝要求固定模型包或重新转换模型作为前置条件，因为以后只保证输入输出契约一致。

语义契约描述数据含义，存储契约描述类型和内存排列。输入灰度像素范围固定为 0～255；Head 分类输出为未转概率的原值，位置输出为左、上、右、下距离。模板和搜索特征分别为 `[1,96,8,8]`、`[1,96,16,16]`。兼容替换需保证特征含义也兼容，而不仅是尺寸相同。

加载时自动检查可查询的属性。颜色、归一化、特征含义由模型提供方保证，并用固定输入对照验证；不声称仅靠 RKNN 属性可以证明语义等价。使用说明列出这项责任，不新增强制的模型清单文件或包身份约束。

后果：兼容权重替换无需编译。数据类型或布局超出首版支持范围时明确拒绝；模型质量变化单独报告，不作为文件身份拒绝理由。

### 2. 三层职责分离

选择如下分层，拒绝在底层增加 YOLO/Backbone/Head 类型分支，也不要求平台内部会话实现公共 `ModelExecutor` 的全部动态能力。

| 层 | 建议文件 | 职责 |
|---|---|---|
| SDK 调用边界 | `rknn_api.*` | 保留可注入的 RKNN 函数；测试可替换失败返回 |
| 单模型会话 | `rknn_session.*` | 加载、描述、输入校验、同步推理、输出复制及失败回收 |
| YOLO 模型语义 | `rknn_yolo_backend.*`、`rknn_yolo_contract.*` | 保留现有输入限制、六输出校验与类别数推导 |
| NanoTrack 模型语义 | `rknn_nanotrack_backend.*`、`rknn_nanotrack_contract.*` | 三模型匹配、模板缓存、调用顺序与输出角色 |

`RknnSession` 表示一个模型及其资源，只接受串行调用。它动态查询输入输出数量；动态数量不意味着动态形状。其描述含索引、名称、已解析尺寸、类型、布局和量化信息。首版仅执行固定正尺寸，遇到未解析维度返回诊断。

会话的输入记录使用平台私有描述：索引、形状、类型、布局、地址、字节数及所有者引用。执行前校验全部输入，包括重复/缺失索引、大小溢出与受支持的类型转换。不同类型的缓冲区不能伪装为 `float*`；现有 YOLO ByteInput 继续作为字节存储。RKNN 原生结构只留在平台私有文件中。

会话输出采用自有 Float32 存储，并保存实际逻辑布局。会话不猜测分类、位置或类别数，不自动做像素归一化、Softmax（把分类原值变为概率）或框解码。后端完成角色识别与必要的 NCHW/NHWC 轴重排；它们分别表示批次、通道、高、宽和批次、高、宽、通道的排列。

后果：YOLO 和 NanoTrack 共享设备安全逻辑，但分别守住模型契约。旧 `RknnRuntime` 可在迁移期间成为薄包装，最终不得保留第二份 SDK 执行实现。

### 3. 用 Float32 衔接模型，兼容不同精度

选择：首版使用普通同步 API，输入 `pass_through=0`，输出 `want_float=1`。FP16 是 16 位浮点；INT8 使用比例 scale 和零点 zp 表示实数。模型原生逻辑属性支持 FP16、Float32，以及有效逐张量仿射 INT8；INT8 的 scale 必须为有限正数、zp 必须在整数范围内。不支持的量化形式或设备私有分块布局明确拒绝。YOLO 仍保留其更严格的检查。

浮点张量可能携带 AFFINE 标记，但类型仍为 FP16/Float32。对这两类张量不使用 scale/zp 判断数值合法性或修改数值；整数反量化规则仅适用于 INT8。会话仍拒绝未支持的量化形式（例如 DFP），并对 INT8 保留有效比例及零点检查。

公共 NanoTrack 图像输入仍为 Float32 NCHW，范围 0～255；根据模型提交要求在平台内部整理排列，不量化回 uint8 图像块。使用现有 Runtime 2.3.0 构建产物，在当前开发板 Runtime 2.3.2 上用固定输入验证实际转换与模型内归一化，避免二次归一化。Head 接收还原后的浮点特征。SDK 已返回 Float32 时，不再执行一次反量化。

拒绝直接把 INT8 Backbone 字节传给 INT8 Head：即便两端类型一致，scale 和 zp 也可能不同。例如 scale=0.1、zp=0 时整数 10 表示 1.0；接收端 scale=0.2 时整数 10 表示 2.0。

后果：全 FP16、全 INT8、FP16 Backbone + INT8 Head、INT8 Backbone + FP16 Head 共用调用链。转换与主机复制有开销，后续优化另行验证；浮点桥接不恢复量化已损失的信息。精度由加载文件决定，不提供宣称可改变模型内部计算精度的运行时开关。

### 4. 三个会话组成一个有状态后端

选择：独立工厂接收三个明确路径，全部加载和检查成功后才返回模型后端与预处理器。拒绝修改当前只接收一个 Backbone 路径的公共 PlatformFactory，因完整 RK3576 装配不属于本次范围。

模型规范化到 NCHW 后的契约：

| 角色 | 输入 | 输出 |
|---|---|---|
| 模板 Backbone | `[1,3,127,127]` | `[1,96,8,8]` |
| 搜索 Backbone | `[1,3,255,255]` | `[1,96,16,16]` |
| Head | 模板特征、搜索特征 | 分类 `[1,2,15,15]`、位置 `[1,4,15,15]` |

Head 输入通过唯一特征形状确定角色并绑定实际索引，不要求固定导出名称；输出通过唯一分类/位置形状识别。拒绝缺失、重复和额外输入输出。

运行顺序：

1. `setTemplate()` 先清除旧模板，再执行模板 Backbone。
2. 检查新特征能供 Head 消费，复制或持有自有输出，成功后标记模板有效。
3. `search()` 检查模板有效，执行搜索 Backbone，再按实际索引提交两份特征给 Head。
4. 把 Head 输出整理成具名 Float32 NCHW 结果，交给 `nanoPrediction()` 与公共框更新逻辑。
5. `reset()` 清除模板有效状态和所有权，可重复调用。

后果：建立目标 B 失败时不能继续使用 A。搜索中的前置校验失败不覆盖模板；若会话因 SDK 错误失效，后续调用返回未就绪，必须重建后端才能恢复。

### 5. 复用灰度几何，明确缓冲区所有权

选择新增 `nanotrack_preprocessor.*`，复用 `calculateNanoCropGeometry()`、`TargetMean` 和可复用输入的租约模式。租约表示旧输入仍被持有期间，缓存不得被下一次准备覆盖。拒绝复用 YOLO 的 uint8 缩放输出，因为这会丢失 NanoTrack 浮点插值结果。

流程是：只读映射 Gray8 帧，取得稳定图像；按原有舍入公式裁剪与填边；转换浮点并线性缩放；复制为三平面。保留均值转 uint8 的现有规则、114 回退、模板重新建立时的均值失效规则。输入结果可以比预处理器存活更久，复用缓存尚被持有时返回 InputBusy。不同平台存储不得通过未检查的强制转换访问。

后果：算法输入语义不变。OpenCV 与 VPI 插值差异需要固定样本测量，不能借移植顺手调整框公式。

### 6. 延续保守的设备失败策略

选择复用既有“确认设备结束后才能释放”的原则，拒绝把负返回值视为设备停止证据。成功获取输出后，复制到自有存储，再释放 SDK 输出；后续推理与会话销毁不影响旧结果。

提交后失败必须确认停止；确认后失效并销毁会话。无法确认设备停止或销毁失败时沿用致命诊断和立即终止策略。获取输出失败时不释放所有权未明确转移的部分 SDK 指针。任何失败不返回部分结果。YOLO 调用方继续先停止并等待工作线程结束，再销毁会话。

后果：多输入支持不削弱既有资源安全；新增测试需覆盖三个模型部分加载失败及模板长期持有。

### 7. 先独立验证，再讨论部署精度

选择在现有 ARM64 独立 CMake 入口中增加 `rk3576_nanotrack_probe`，保留 `rk3576_yolo_probe` 和原有构建用法。命令参数包括 `--template-model`、`--search-model`、`--head-model`，以及 `--mode query|replay`。query 输出三模型属性、角色映射和运行时版本；replay 接受视频与首帧 `--bbox x,y,w,h`，输出帧号、成功状态、框、置信度和耗时。彩色视频明确转为 Gray8 后进入公共跟踪器，不隐式改变模型输入语义。

拒绝在本变更中开放完整平台选择，因为采集与整套依赖仍不齐全。首选全 FP16 做正确性基线，但不把它硬编码为唯一可接受模型。最终部署的质量/性能门槛不属于后端加载条件。

验证包括三层：

1. 注入 SDK 测试检查格式、索引、独立存储和失败路径；已知样例中的量化转换结果应与数学期望一致。
2. 同一模型、同一浮点裁剪张量对比独立参考执行与 C++ 后端的特征和 Head 输出。先运行相同输入确定重复执行误差，再记录容差，不能通过调整跟踪阈值掩盖差异。
3. 相同视频与首帧框分别回放四种精度组合，报告框重叠、中心误差、置信度、漂移、平均/P95 延迟和内存趋势。P95 是 95% 帧不超过的耗时。模型质量损失与后端适配错误分开判断；不要求 INT8 与 FP16 逐帧数值相同。

为避免重写算法，回放入口复用真实 NanoTracker。没有完整工厂时，YOLO/NanoTrack 共存压力检查可由测试程序分别装配两者完成，不宣称完整 ROS 验收。

## Risks / Trade-offs

- 模型属性无法证明语义相同 → 文档明确提供方责任，并用实际浮点输入进行特征和输出对照；不设置身份白名单。
- SDK 转换可能与已有 uint8 评估路径不同 → 验证浮点图像输入与 Head 特征转换，不照搬彩色评估结论。
- 通用层提取影响既有 YOLO → 先通过原契约、失败注入和真实检测回归，再接入 NanoTrack。
- 模型输出排列变化 → 保留实际布局，按语义轴转换，拒绝未支持的设备私有格式。
- 同时运行 YOLO 与 NanoTrack 争用设备 → 使用不同会话，禁止同会话并发；实机测量共存延迟和停止流程。
- 缺少 Jetson 验证环境 → 单独记录尚未取得的跨平台证据，不用 ARM64 构建或 RK3576 回放代替。

## Migration Plan

1. 提取会话并迁移 YOLO；保留已有命令、参数和拒绝条件，运行回归。
2. 接入 NanoTrack 三模型、预处理器和独立回放，执行契约测试。
3. 在既有目标构建环境编译，按本地环境约定访问 RK3576，记录版本、模型和输入证据。
4. 更新平台说明与重构进度，只报告独立接入完成。模型文件不进入普通源码仓库。

回退以移除新增独立入口并恢复提取前的 YOLO 执行实现为单位；不涉及 ROS 配置迁移。部署选择可通过重新启动并指定另一组兼容模型路径回退，不支持运行中的热切换。
