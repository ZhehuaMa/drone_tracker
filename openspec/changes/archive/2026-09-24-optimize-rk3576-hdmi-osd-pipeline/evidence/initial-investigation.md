# HDMI OSD 优化验证记录

## 当前结论（2026-09-24）

本变更尚未完成实施。生产板前置探针发现当前设计的两个限制，已获得用户确认修订，继续实现。正式节点、部署配置、模型和系统调度设置未修改。探针只使用合成内存图像，不采集相机、不打开 DRM 显示设备、不运行跟踪器。

1. `Gray8`（每像素一个灰度字节）直接通过一次 RGA 调用转换到 BGRA，接口返回成功，但颜色不正确。全灰 128 的初步检查通过，连续变化图像才暴露问题，不能凭返回值或单一灰阶验收。
2. `Bgr8`（每像素三个颜色字节）的 RGA `wstride` 以整数像素计。设计中的 4096 字节行跨度不能被 3 整除，不能精确表达。向下或向上取整均被本板 RGA 拒绝。改用 DMA 句柄本身不能解决行跨度表达问题。

2026-09-24 用户已确认修订：灰度允许两次同步 RGA 操作，先缩放到中性色度的持久缓冲，再转换到主平面；兼容的 BGR 保持一次操作；无法直接表达的步长允许在平台边界重排到可复用缓冲。保留消除视频额外复制、全帧 HUD 混合、缓存布局及所有性能门槛的目标。该方案已同步到 proposal、design、规格及任务清单。

## RGA 探针结果

虚拟地址先用 `importbuffer_virtualaddr` 导入句柄，再与目标 DMA 句柄一起交给 RGA。直接混用虚拟地址包装与目标导入句柄会被 librga 拒绝，不能将这种调用方式错误判为虚拟地址输入不支持。

连续探针每帧改变像素，逐帧同步完成后检查 5 行 × 4 列 × 3 通道，共 60 帧、3600 个通道样本。允许误差为 2 个灰度级。它验证抽样像素和基本同步使用，不能替代正式 `FrameReadView` 生命周期、缩放边界、显示及满负载验收。

| 路径 | 格式 | 字节步长 | 帧数 | 调用失败 | 超容差样本 |
|---|---|---:|---:|---:|---:|
| 单次直接转换 | Gray8 | 1280 | 60 | 0 | 3488 |
| 单次直接转换 | Gray8 | 1296 | 60 | 0 | 3488 |
| 单次直接转换 | Bgr8 | 3840 | 60 | 0 | 0 |
| 单次直接转换 | Bgr8 | 3888 | 60 | 0 | 0 |
| 单次直接转换 | Bgr8 | 4096，像素步长取 1365 | 1 | 1 | 不适用 |
| 单次直接转换 | Bgr8 | 4096，像素步长取 1366 | 1 | 1 | 不适用 |
| 两步灰度对照 | Gray8 | 1280 | 60 | 0 | 0 |
| 两步灰度对照 | Gray8 | 1296 | 60 | 0 | 0 |

直接灰度的具体错误：输入黑色 0，在首行首像素的绿色通道得到 135。两步对照把灰度写入 Y 平面，并让 UV 色度平面保持 128，再按 BT.601 全范围转成 BGRA；这保留了现有后端的灰度处理方式。

源码和输出保存在 [evidence]()：`source_probe.cpp`、`stride_probe.cpp`、`two_pass_probe.cpp` 及对应日志。辅助 `dma_buffer.h/.cpp` 使用本仓库当前版本。

复现（从仓库根目录运行，生产板须可访问）：

```bash
scp openspec/changes/optimize-rk3576-hdmi-osd-pipeline/evidence/*_probe.cpp \
  src/platform/rk3576/osd/dma_buffer.h src/platform/rk3576/osd/dma_buffer.cpp \

ssh firefly-production 'source /opt/ros/humble/setup.bash; g++ -std=c++17 -O2 /tmp/stride_probe.cpp /tmp/dma_buffer.cpp -I/usr/include/rga -lrga -o /tmp/drone-osd-stride-probe && /tmp/drone-osd-stride-probe'

```
