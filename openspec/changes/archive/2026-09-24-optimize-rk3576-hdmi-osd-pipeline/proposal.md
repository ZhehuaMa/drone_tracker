# Proposal

## Why

当前 RK3576 HDMI OSD 在完整跟踪负载下存在明显延迟和卡顿。生产板实测显示，采集约为 60.384 fps、跟踪消费约为 34.680 fps，但 HDMI 实际显示仅约 2.416 fps；单帧 OSD 渲染总耗时均值约 422.67 ms，提交到显示的延迟均值约 439.29 ms。画面更新速度远低于输入和跟踪速度，因此用户看到的是滞后数百毫秒、约每 0.4 秒才更新一次的画面。

主要耗时来自两类重复工作：一是每帧用 OpenCV 重新绘制整张 HUD 和目标图层；二是视频帧在 CPU、RGA 中间缓冲和 DRM 主平面之间发生多次全帧复制与混合。参考实现 `rk_hdmi_osd/osd_bridge` 通过持久化图层、字形缓存和更短的 RGA/DRM 路径避免了这些开销。本变更在保持现有帧与遥测严格配对、OSD 关闭冻结画面、ROS 接口和故障隔离语义不变的前提下，将本仓库的显示路径改造成适合持续实时输出的缓存式管线。

完成后，同一生产板、同一模型和同一输入录像下，优化路径应将稳定阶段的 OSD 渲染总耗时均值降至 40 ms 以内，并使 HDMI 新视频帧显示速率达到至少 25 fps。旧路径保留为启动时可选的回退路径，便于实机对照和故障回退。

## What Changes

- 新增缓存式 HDMI OSD 渲染路径：主平面双缓冲直接保存缩放和格式转换后的纯视频；覆盖平面双缓冲保存持久化 RGBA OSD 画布，不再为每帧创建和清空完整 OpenCV 图层。
- 将固定边框、标签背景和可复用文字字形缓存起来，只在内容或脏区域变化时更新 OSD 画布；几何尺寸不变时不重复初始化黑色、色度和临时缓冲。
- 使用同步 RGA 调用直接读取 `FrameReadView` 暴露的源图像内存，并让读视图存活到 RGA 完成，消除兼容布局下源帧到 DMA 输入缓冲的第二次 CPU 全帧复制；仅对硬件无法表达的行布局使用可复用缓冲重排。若生产驱动不支持该虚拟地址路径，则采用平台私有的 DMA 帧视图并保持采集缓冲所有权到同步处理完成，禁止提前归还 V4L2 缓冲。
- 删除优化路径中的中间视频双缓冲、纯视频到主平面的额外复制以及 HUD 与视频的全帧 RGA 混合。兼容 BGR 视频以一次同步 RGA 操作写入主平面后备缓冲；灰度以两次同步操作保持中性色彩，OSD 画布复制到覆盖平面后备缓冲，再通过一次 DRM 原子提交配对显示。
- 分离主平面和覆盖平面的“已显示”与“已准备”索引。只有 DRM 提交和翻页事件成功后才更新已显示状态；仅遥测变化或 OSD 关闭冻结时复用当前主平面，只更新覆盖平面，仍保持视频、目标框和状态的原子配对语义。
- 增加启动参数 `osd.render_path`，取值为 `cached-overlay` 或 `legacy`。完成验收后默认使用 `cached-overlay`，`legacy` 用于对照测试和现场回退；运行中不热切换。
- 更新阶段耗时诊断，将优化路径的源处理阶段报告为 `source_prepare`，并继续单独报告布局更新、覆盖层上传、DRM 提交、翻页等待、提交到显示延迟和新视频帧间隔。旧路径保留原有 `source_copy` 标签，避免混淆两种路径的含义。
- 增加同板 A/B、颜色与步长、配对一致性、OSD 开关、10 分钟满负载和异常退出验证。默认行为不得修改 CPU governor、进程优先级或线程亲和性；只有独立证据证明必要时，才允许通过显式配置进行可选绑定。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `rk3576-hdmi-osd`：扩展 RK3576 HDMI OSD 的渲染管线、启动配置、阶段耗时诊断和生产板性能验收要求，同时保持已有显示语义和故障隔离要求。

## Impact

- 主要影响 `src/osd/` 的布局渲染，以及 `src/platform/rk3576/osd/` 的 RGA 缓冲组织、DRM 原子提交和阶段计时。
- 需要更新参数声明、RK3576 参数 YAML、启动配置说明和 OSD 运维文档，说明 `osd.render_path` 的默认值、回退方法和诊断指标。
- 需要补充缓存布局、缓冲索引状态机、源视图生命周期和渲染路径选择的单元测试或主机侧替身测试。
- 实机验收必须使用指定的 HZ-RK3576_WuKong Board、系统 RKNN Runtime 2.3.2、RKNPU 驱动 0.9.8、真实模型和固定回放输入。非目标主机的测试不能替代显示性能结论。
- 不改变现有 ROS 话题、消息类型、跟踪状态数值、模型前后处理、`OsdPresenter` 的帧遥测配对规则或默认系统调度策略。
