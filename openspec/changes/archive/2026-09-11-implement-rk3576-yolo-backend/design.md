## Context

程序目前不能在 RK3576 上运行已有 YOLO 模型，且目标参数会接受多个类别。目标是让独立检测入口正确运行该模型，并且只报告配置的一类目标。动机和范围见 [proposal.md](proposal.md)。

现有 `YoloBackend` 提供模型能力，`YoloPreprocessor` 准备图像，`YoloV8Detector` 管理工作线程和检测级联。公共输入检查固定使用 Float32 NCHW（32 位浮点数，按批次、通道、高、宽排列）。公共后处理读取三维合并预测。顶层 CMake 仍拒绝 RK3576 完整生产构建，平台工厂要求整套 YOLO、NanoTrack 与帧组件。

2026-09-10 在 RK3576 上只读查询并运行的证据如下。模型相对测试目录路径为 `models/yolov8n-model_zoo-int8_fp16-multi_cls.rknn`，SHA-256 为 `4d8a22bc8da9fbbc43f190b7ea90c27d9980f77e3e27064ec32cf6566c2680f3`。同哈希转换记录说明 mean=0、std=255，输出为三组框分布和类别原始分数。运行时版本为 2.3.0，驱动为 0.9.8。

| 张量 | 形状 | 原生类型 | 零点 / 比例 |
|---|---|---|---|
| images | `[1,640,640,3]` | INT8，NHWC | -128 / 0.003921568859 |
| 框 0 | `[1,64,80,80]` | INT8 | 43 / 0.525237918 |
| 类别 0 | `[1,4,80,80]` | FP16 | 查询为 0 / 1 |
| 框 1 | `[1,64,40,40]` | INT8 | 91 / 0.995672822 |
| 类别 1 | `[1,4,40,40]` | FP16 | 查询为 0 / 1 |
| 框 2 | `[1,64,20,20]` | INT8 | -12 / 0.368377268 |
| 类别 2 | `[1,4,20,20]` | FP16 | 查询为 0 / 1 |

NHWC 按批次、高、宽、通道排列。量化使用零点与比例将整数解释为实数；它不同于输入像素除以 255。FP16 是半精度浮点数，不能仅凭查询中的量化标签把它当整数再次反量化。

板上已有 RKNNLite 2.3.0 对 UINT8 NHWC 的全 0、114、255 输入均返回六份有限 Float32 输出。这是模型结构和执行冒烟证据，不是 C++ 后端、真实图像精度或性能验收。同源 ONNX 元数据记录类别 0 AIRPLANE、1 BIRD、2 DRONE、3 HELICOPTER；此映射不适用于所有后续模型。

## Goals / Non-Goals

**Goals:**

- 让真实公共检测器消费 RKNN 输出，数学转换可脱离设备测试。
- 让兼容模型替换仅需路径和目标编号配置，不依赖文件名或固定类别数。
- 显式表达输入存储格式，保持网络收到的灰度像素语义。
- 把设备所有权、同步和错误限制在平台内部。

**Non-Goals:**

- 完整 RK3576 ROS 节点、NanoTrack 推理、相机或硬件解码、运行时平台切换。
- 性能评估、吞吐或延迟指标、RGA 图像加速、零拷贝及量化优化。
- 动态尺寸、九输出模型、输出已为概率的变体、任意 YOLO 家族自动识别、运行中热换模型或类别。

## Decisions

### 1. 按结构接受模型，不绑定权重

选择六输出固定顺序契约：索引 0/2/4 是框，1/3/5 是类别；尺度依次为 80、40、20。框通道固定 64，三个类别通道必须为同一正数 C。固定顺序避免 C=64 时仅凭形状误认输出角色。名称用于诊断，不绑定当前导出节点名。初始化查询完整属性，检查正尺寸、大小乘法溢出、输出数量和支持的类型。输入固定 INT8 NHWC 640×640×3 及已确认量化语义；输出支持 INT8、FP16、Float32，整数输出要求有效正比例及受支持的量化方式，参数逐张量读取。

不采用哈希白名单，也不凭形状自动猜测 Sigmoid 是否已经包含在图中。结果是可以换权重和类别数，但模型提供者仍须保证 mean/std、六输出角色及原始分数语义；这类语义无法完全由 RKNN 形状查询证明。验证记录保存哈希、契约和转换来源，合成契约测试覆盖 C=1、4、6、64 及更大合法类别数。

### 2. 公共契约描述实际提交存储

选择为 `TensorLayout` 增加 NHWC，并使 `ModelInputContract` 的 shape/type/layout/scale/offset 始终描述准备结果中的实际数据。RKNN 是 UINT8 `[1,640,640,3]`、scale=1、offset=0；Jetson 继续是 Float32 `[1,3,H,W]`、scale=1/255、offset=0。RKNN 内部另行记录网络归一化契约 mean=0/std=255。以专用 YOLO 校验和尺寸解析替换检测器对 `shape[2]/shape[3]` 的固定假设，不放宽 NanoTrack 的检查。

不采用“浮点契约隐藏 UINT8 存储”，也不让通用 `TensorStorage::hostData()` 返回伪装成 float 的字节缓冲。RKNN 准备输入通过平台私有派生类型保存字节存储，推理入口检查真实类型。结果是公共算法能够正确取到宽高，Jetson 旧输入不变，RKNN 不会重复除以 255。

### 3. OpenCV 预处理与独立快照

选择 `Frame::mapRead()` 读取 Gray8，检查映射尺寸、格式和行跨度，在租约内复制到独立快照后立即释放源映射和源帧引用。每个区域复用 `resolveYoloRegion` 和 `calculateLetterboxTransform`。使用 U8 线性缩放、114 边距填充，再复制灰度到三个交错通道。缓存沿用 `ReusableInput` 的持有期间不可覆盖约定。

不立即采用 RGA，也不接受 BGR 帧后隐式转换颜色。结果是无需额外 SDK 即可测试像素与几何；OpenCV 和 VPI 的插值可能有舍入差异，须按固定输入记录差异，不能宣称逐位等价。

### 4. 平台内同步执行，输出转为自有 Float32

选择在 `src/platform/rk3576/` 增加私有 Runtime 封装及 `RknnYoloBackend`。封装不为本次 YOLO 强行扩展成支持所有模型的通用执行器。它管理 context、原生属性和 SDK 调用；后端对接 `YoloBackend`。一个 context 只供一个工作线程串行推理，初始化发生在检测线程启动前，销毁发生在 stop/join 后。

先使用 `rknn_inputs_set`，UINT8 NHWC、`pass_through=0`，随后 `rknn_run` 和 `rknn_outputs_get(want_float=1)`。成功后把逻辑连续输出复制到自有 Float32 存储，再调用 `rknn_outputs_release`。不使用原生带跨度缓冲作为连续数组。测试核对 get 返回的字节数与逻辑元素数量，尤其 FP16 原生输出。

不选择零拷贝或共享可覆盖的输出指针。结果是旧输出可以比执行器活得更久。初始化失败回收已得资源，执行失败不返回部分输出；可确认设备停止的失败使 context 失效，不能确认停止的失败按既有致命错误契约终止。实现时必须依据 2.3.0 API 明确区分这些路径，不能假定任意负返回值都已同步。

### 5. 六输出适配使用公共纯数学模块

选择新增 `model/yolo_output_adapter.*`，输入为反量化后的浮点张量，输出为 `[1,4+C,8400]`。DFL（分布式边界距离表示）对四边各 16 个分数做稳定 Softmax，再计算 0～15 的期望距离。Softmax 将一组分数转换为总和为 1 的概率；稳定计算先减去最大分数，避免指数溢出。Sigmoid 将每个类别原始分数独立变成概率。按尺度 80、40、20，再按行优先顺序拼接。

网格中心为 `(x+0.5,y+0.5)`，步长为 8、16、32。先算模型像素坐标下的四边，再转为中心坐标 cx、cy 和宽高 w、h。letterbox 是等比例缩放后填充边距的操作，ROI 是优先检测区域。适配层不减 letterbox、不加 ROI 偏移、不按类别或阈值提前裁剪候选，也不做 NMS（去除高度重叠的重复框）。非有限输入或输出拒绝整次结果。

不把 RKNN 六输出直接塞入现有三维校验，也不复制官方示例中的最终筛选流程。结果是 Jetson 已合并预测仍可直接使用，公共后处理继续承担原图坐标还原与框大小筛选。将现有 `yoloPrediction` 的轴大小启发式改为显式属性轴 1、候选轴 2 的约定，避免类别数增加后把合法输出误判为转置；不新增转置布局支持。

### 6. 单类别参数在 NMS 前生效

选择沿用 `tracker.yolo_target_class_id`，初始化配置一次，语义改为精确编号。给 `YoloBackend` 增加可查询类别数的能力，Jetson 从已解析输出属性取得 C，RKNN 从六输出取得 C。初始化要求 `0 <= id < C`，不启动工作线程处理无效配置。输出消费时再次验证类别数没有改变。

公共后处理只读 `4+id` 通道，按该阶段原有阈值及框大小规则筛选，然后使用现有 NMS。级联收集要求精确类别相等。不同类别的更高分不影响目标分数，也不会抑制目标框。

不使用“先全类别 argmax 再过滤”，因为会丢弃目标分数已经合格的候选。结果是此修改对所有平台生效，是明确的兼容性变化；默认编号仍为 0，两个 YAML 和头文件说明更新，部署者必须检查各模型类别映射。

完整请求示例：

1. 配置类别 2，提交 Gray8 图像和 ROI（优先检测区域）。
2. 从独立快照裁剪、缩放、填充，提交 UINT8 NHWC。
3. 同步取得六输出，转换为含四类分数的 `[1,8,8400]`。
4. 某候选鸟分数 0.8、无人机分数 0.7，ROI 阈值 0.5；按 0.7 进入原图坐标还原和目标类 NMS。
5. ROI 命中后返回原帧号和最高分目标框，不执行全图或切片。

### 7. 独立构建边界和验证入口

选择新增 `src/platform/rk3576/CMakeLists.txt` 作为可独立配置的 C++17 工程，链接 RKNN 与公共算法，不链接 ROS 或 Jetson SDK。按需整理公共 CMake 以复用相同目标；已有 `DRONE_TRACKER_PREPROCESS_TESTS_ONLY` 路径继续工作。构建产生 `rk3576_yolo_probe`，接受模型路径、输入图像/视频路径和目标编号，提供契约查询、单区域比较及真实异步检测模式。图像转 Gray8 在工具输入边界显式完成。工具使用自有主机帧实现，不伪造完整 `PlatformFactory`。

不直接开放顶层 `DRONE_TRACKER_PLATFORM=rk3576`，因为 NanoTrack 和采集尚未实现。结果是完整生产平台选择测试保持有效，独立入口另有构建测试。RKNN 头文件及库发现采用显式缓存路径，缺失时给出版本及路径诊断；容器遵守 `AGENTS.local.md`，不重建环境镜像。

## Risks / Trade-offs

- [模型元数据不能证明完整语义] → 用转换记录确认 logits（未经 Sigmoid 的原始分数）与 mean/std；替换模型仍需执行固定样本正确性验证，哈希只追溯。
- [量化结果与浮点模型不同] → 将适配器数学正确性和模型量化精度分开。固定浮点张量对照使用 `atol=1e-4, rtol=1e-5`；同一 RKNN 输入的 C API 与 RKNNLite 浮点输出对照使用 `atol=1e-5, rtol=1e-5`。atol 是绝对容差，rtol 是相对容差，逐元素要求 `|实际值-参考值| <= atol + rtol*|参考值|`。超差先调查，不擅自扩大容差。
- [灰度与原有彩色评测不一致] → 同源 ONNX 和 RKNN 比较使用同一灰度三通道输入；既有彩色评测不能直接证明本管线精度。
- [插值和阈值附近差异] → 几何及 0/114/255 数值测试要求精确，非平凡缩放记录像素误差；跨平台检测精度和逐帧等价性不在缺少 Jetson 时宣称完成。
- [线程资源错误] → 故障注入覆盖输入、run、get、release 和停止边界；重复创建销毁与有限连续运行检查泄漏和死锁，不测性能。
- [默认编号 0 不再代表接受全部类别] → 发布说明明确迁移，四类别无人机示例显式配置 2，绝不根据文件名推断编号。

## Migration Plan

1. 实现公共契约扩展、数学适配及单类别规则，通过无硬件测试；保持 Jetson 输入格式和默认模型路径。
2. 实现 RKNN 私有封装、OpenCV 预处理和独立工具，在约定 ARM64 环境构建。
3. 使用上述实机模型与固定灰度图像/录像验证。记录样本路径和哈希、版本、原生属性、目标编号、浮点输出对照、最终框及错误记录。重放相同输入要求结果可重复。
4. 对比板上已有 RKNNLite 的原始输出；最终框参考必须采用本次目标分数规则与现有公共 NMS，不能拿旧的按类别分组 NMS 结果直接验收。对真实图像的精度报告只说明实际观察，不设性能或未经确认的量化精度门槛。
5. 发布独立入口使用说明与目标参数迁移说明，标注未执行的 Jetson 实机检查。完整跟踪工厂后续另立变更。
6. 回滚时撤销本变更代码和参数语义说明，恢复此前检测规则。运行模型文件不被本变更覆盖或删除，验证结果作为外部证据保留。
