# Design

## Context

当前 HDMI 画面能稳定配对视频、目标框和遥测，但 HUD 的排版与参考项目明显不同。本设计在保留本仓库显示链路和安全提示的前提下，复现参考项目 `rk_hdmi_osd` 提交 `3e605a26c7c135b468ef2a3638ffd47144594603` 的视觉语言。HUD 是视频上的信息层；参考项目的外观由 `layout/layout.cpp` 的元素位置、`osd/osd.cpp` 的图形画法和 `osd/osd_font.h` 的点阵字共同决定。

本仓库已具备两条 HDMI 渲染路径。`legacy` 每次重画完整画布，`cached-overlay` 缓存不变区域以减少绘制工作。两者都经 `src/osd/layout.*` 生成画面。本仓库只接收一个真实目标框，框数据不含置信度或目标编号。现有 `osd-presentation` 规格还要求帧框同次提交、冻结时清框，并保留独立中文状态提示；这些约束高于参考演示数据的外观细节。

## Goals / Non-Goals

**Goals:**
- 在 720×480 逻辑画布上复现参考 HUD 的元素、位置、配色、字形、角框和动画节奏；其他支持的分辨率统一缩放。
- 让两条现有渲染路径输出相同内容，同时保留 `cached-overlay` 的增量绘制与两层配对提交。
- 为缺失、过期和本仓库不存在的字段规定清晰显示方式，并留出中文冻结/故障提示区域。

**Non-Goals:**
- 移植参考仓库的独立 ROS 桥接节点、相机采集、RGA 合成或 DRM 管线。
- 加入演示用第二目标、模拟置信度、目标编号或新的 ROS 话题。
- 修改跟踪状态机、算法输出、采集时间、ROS 消息、模型或录像行为。

## Decisions

### 1. 固定视觉基准并在本仓库维护绘制资源

**选择：** 将参考提交的布局坐标、调色板、16×32 和 8×16 字形、角标、圆环准星、俯仰梯、返航箭头、电量条及目标角框作为移植依据。只把需要的纯 CPU 绘制代码和资源整理到本仓库，保留其来源、许可证和生成说明。已有中文状态字形单独保留。先生成参考项目的独立快照，再生成相同输入的本仓库快照。

**原因：** 只调 OpenCV 字号无法同时匹配点阵字宽、黑描边和目标标签底板。固定提交使以后参考仓库改动不会悄悄改变验收标准。

**未采用：** 运行时链接本机 `rk_hdmi_osd`，或把其硬件后端整体移植。本仓库已有经过验收的帧所有权与显示管线；依赖外部目录还违反现有 `rk3576-hdmi-osd` 规格。

**结果：** 参考项目不在机器上时仍可构建和运行。字体资源入库前核对 `osd_font.h` 的生成源与授权文本；无法确认可再分发时，使用授权清晰且度量匹配的替代字形，并在像素差异报告中标明。

### 2. 一份布局语义，分别适配完整重画和缓存重画

**选择：** 在 `src/osd/layout.*` 建立共同的 720×480 元素描述和绘制原语。完整重画按该描述每次绘制；缓存重画按相同元素 ID、几何范围及内容键更新脏区域。目标框仍使用独立覆盖层，视频与覆盖层继续在同次 DRM 更新中显示。脏区域指需要重新上传的画布矩形。

**原因：** 两路径分别抄一份参考布局容易在数值变化、告警闪烁或缩放时产生视觉分叉。沿用当前显示缓冲所有权与原子提交，减少改动范围。

**未采用：** 只改 `legacy` 再让 `cached-overlay` 降级为每帧完整重画。这会绕过现有生产默认路径的增量性能目标。

**结果：** 快照测试可逐像素比较两路径；缓存路径还需验证静态帧不重复栅格化，动态文字变短、目标移动及闪烁时无残影。

### 3. 将参考元素映射到真实可用的数据

**选择：** 按下面顺序组织每次显示：

1. 现有消费者提交帧、真实单目标框、本地跟踪状态和轮内序号；显示侧不重新取相机画面。
2. 遥测适配器汇总新鲜数据。模式、解锁、姿态、位置、电池和温度使用已有快照；卫星定位等级由 `GPSRAW.fix_type` 明确暴露，不以卫星数量猜测。必要时在显示侧快照增加可信的剩余比例、告警等级或触发事件字段，不增加订阅源。
3. 布局把有效数据格式化为参考项目的短文本。地速从 m/s 转为 km/h。电量条仅使用有效剩余比例。返航箭头仍使用现有相对方位。时钟使用本地系统日历时间并在文档注明，不把采集时间戳误当作日历时间；底部 `F` 使用已消费帧的轮内序号。
4. 当标签没有真实目标名称时，底板使用本地跟踪状态文字；不显示百分比或目标 ID。跟踪状态颜色沿用现有白、青、绿、红映射。
5. 通过同一次显示更新提交视频底图与目标覆盖层。冻结、过期和无框状态清除目标层；遥测仍可单独刷新。

**原因：** 参考演示结构中数值字段默认可用，而生产数据存在缺失和过期。显示“0”会让操作者误以为测量有效。

**未采用：** 直接填充参考 `Telemetry` 结构的默认零值，或从 ROS `/fpv/target_bbox` 回订阅框。前者制造假读数，后者破坏进程内严格配对。

**结果：** 数值缺失时显示 `--` 或隐藏。带百分比与编号的演示标签只进入参考快照，不进入正式 HDMI；两侧相同输入对照时把这些字段列为明确例外。

### 4. 保留中文状态提示的优先显示区

**选择：** 实时画面使用参考项目底部消息、解锁或触发与告警排布。等待、冻结、EOF 或故障时，底部中间消息区让位给本仓库现有中文提示；告警保持在独立右侧区域。触发事件由现有 `/fpv/tracker_trigger` 回调送入显示侧的短时事件槽，使用单调时钟计时，约两秒后清除。仅当前显示轮次可显示其事件。

**原因：** 中文冻结和故障提示是现有已验收行为，不能被参考样式的普通消息覆盖。事件必须与 ON/OFF 轮次隔离。

**未采用：** 用参考项目的 `TRIG OFF` 文字代替“画面已冻结：输入已停止”。短事件不等于持续的冻结状态。

**结果：** 参考风格在实时状态完整呈现；非实时状态保留可读安全提示。测试需覆盖告警与冻结同时出现、重复 ON、迟到旧轮事件和告警闪烁。

### 5. 用真实参考栅格和生产 HDMI 分层验收

**选择：** 在无显示硬件环境先运行参考 `test_layout_snapshot` 或等价纯 CPU 入口，固定示例数据和帧时刻；用本仓库同输入快照核对主要像素区域。单独列出由中文提示、真实字段缺失和字体许可导致的预期差异。再运行本仓库布局、配对及 ROS 回归测试。最后在生产 HZ-RK3576_WuKong Board 上，以同一模型和输入确认可读性、颜色、透明度、帧框配对、退出清理及既有显示性能门槛。

**原因：** 图像快照能稳定检出位置和字形偏差，但不能证明 RGA/DRM 的实际混合效果。生产板验收也难以单独定位每个像素错误，两层证据互补。

**未采用：** 仅凭上一轮手绘对比示意图或主机测试宣布“完全对齐”。示意图没有运行实际渲染器。

**结果：** 验收记录同时给出基准提交、输入、快照、差异区域、目标板身份和未完成项。参考仓库的演示硬件测试只作依据，不代替本仓库实机验证。

## Risks / Trade-offs

- **[字形和许可不匹配]** → 核对参考字库生成器、原字体授权和资源指纹；保留授权声明，并用固定文本快照检查字宽与描边。
- **[大字占用更多画面，遮住目标]** → 使用参考 720×480 的固定信息区；目标层按真实视频范围裁剪，冻结提示优先；在实机观察常见目标位置。
- **[缓存重画遗漏旧字或旧框]** → 用新旧绘制足迹的并集擦除，覆盖文字缩短、框移动、告警闪烁和尺寸切换。
- **[透明叠加在 RGA 与 DRM 上结果不同]** → 沿用现有双层显示路径，并在生产板检查标签底板、文字描边及边缘白晕。
- **[新增 HUD 绘制影响帧率]** → 保留静态缓存与增量更新；按 `rk3576-hdmi-osd` 现有性能门槛同板测量，若未达标则不能宣布完成。

## Migration Plan

1. 先在本仓库实现并通过无硬件快照与回归测试，保留当前 OSD 可构建版本作为回退包。
2. 用现有可回退发布流程部署到生产板，记录程序、配置、模型和系统库身份；不改变系统 RKNN Runtime。
3. 在相同输入上检查 HDMI 正常、冻结、告警和启停，再进行持续负载。完成前不把主机快照标为生产验收。
4. 若画面不可读、配对异常或性能未达门槛，切回上一已验收发布包和原配置；OSD 关闭开关仍可用于故障隔离。
