CPU 亲和性是线程允许执行的 CPU 集合。掩码表示该集合，工作点 CPU 表示调用当时实际运行的核心。PID/TID 分别是进程和 Linux 线程标识。供帧线程按原录像时间供应输入；Tracking 线程执行跟踪更新；YOLO 线程执行异步检测。

## 交付的实现范围

- 回归配置增加可选的 `cpu_affinity` 版本 1 和共同 `cpu_observation`。旧配置和仅 `supplier_cpu` 配置保持可用；非法字段、离线核心、初始允许集合、内核控制组限制及外部策略冲突会被拒绝。
- 由回归控制器生成私有生产格式策略。生产 `deployment/cpu-affinity.yaml` 未修改，模型、NPU 分配、优先级、调频、ROS 接口和参数默认值未修改。
- `RealtimeSource` 拥有提前就绪的 supplier。就绪只绑定并停驻，不创建回放时钟、不供应像素或姿态；放行时复用该线程。取消、失败和重复停止负责唤醒及回收。
- 公共诊断调用点增加默认关闭的位置接收器。回归入口安装预分配的独立写者数组，保存更新、初始化、补跟踪、YOLO 和发布位置。原事件布局仍为 256 字节，CRC、事件配对和完整结束规则不变。
- 外部监督记录模型就绪和回放结束快照，并在期间每秒至多扫描一次线程。未登记的库或中间件线程保留未知归属，不猜测线程数量或重绑它们。
- 普通比较继续要求 CPU 策略完全一致。显式亲和性实验只允许冻结清单中的精确字段和值；完整保存双侧身份，不排除整个 CPU、驱动工具或观测对象。

## 第一轮正式实测失败

唯一板卡连接为 `adb -s 5ceb49407502303d`，没有使用 SSH。该具体板为 HZ-RK3576_WuKong Board，实际内存 8112044 KiB，内核 `6.1.141-rt36`。CPU 0–3 为 A53，4–7 为 A72，隔离 4–7。系统 Runtime 2.3.2 哈希及驱动 0.9.8 复核通过。

运行前冻结了十八轮交替顺序和三个精确处理清单。第一轮是 `[20,35)` 的未绑定参考。保留全帧预解码、supplier 4、准备 3600 秒、收尾 10 秒、迟到 50000 微秒和队列 32。原素材及模型只读复用，哈希与历史来源重新比对通过。

该轮 900 帧均供应，发布 900 次，有效框为 0。帧 1–12 超过供应迟到门槛，节点退出 1，日志进程退出 0。外部截止没有超时，测试资源全部回收。零有效框和失败记录均保留。

第 1 号帧的关键证据如下：

| 边界 | 实测值 |
|---|---:|
| 最初唤醒迟到 | 58.061 微秒 |
| 复制调用墙钟耗时 | 210.925804 毫秒 |
| 复制期间线程 CPU 时间 | 2.506417 毫秒 |
| 墙钟减线程 CPU 时间 | 208.419387 毫秒 |
| 复制后重获队列锁 | 8.004 微秒 |
| 姿态回调 | 4.071 微秒 |
| 最终供应迟到 | 210.996975 毫秒 |
| 主动/被动线程切换 | 11/3 |
| 次要/主要缺页 | 563/0 |
| 唤醒、复制结束、锁读回 CPU | 4/4/4 |

墙钟是实际经过的时间，线程 CPU 时间只计线程执行时间。延迟位于 `copyGrayFrame` 调用内部，而非最初唤醒或复制后的队列锁。首次 YOLO 预处理在约 `m0+15.999 ms` 至 `m0+237.397 ms` 之间，与其重叠，但不能据此推断因果。

只读代码检查确认：供应器在复制前释放队列锁，`copyGrayFrame` 通过 `make_shared` 和 `HostFrame` 的 `cv::Mat::clone()` 分配并复制像素。可见项目代码没有在该调用外持有队列锁。保留证据不能识别 OpenCV、分配器或内核内部的具体等待原因。未进行推测性修改，也未放宽 50 毫秒门槛。

CPU 位置观测本身通过：10608 条记录，无溢出，参考实际范围保持未绑定。整体运行仍因供应迟到不合格。候选没有运行，不能声称其放置或性能已通过。
