# 固定工作量归因实验设计

本实验回答基础诊断模式的额外成本来自哪里。它固定业务实际执行的工作，避免异步检测结果在不同调用返回、因而改变补跟踪步数。它不是任务7.3要求的完整ROS管线十组成对验收，不能据它勾选任务或放宽0.2ms门槛。

1. 通过正式帧源使用的`MjpegVideoReader`读取既有固定视频首帧。该读取器直接取得JPEG亮度平面。用同一个Gray8图像（每像素一个8位灰度数值）构造40帧，时间从1000000微秒起按16667微秒递增。所有模式都逐一调用，不读取最新帧队列。
2. 在预热前用真实YOLO模型执行一次首帧检测，保存真实框和分数。测量期间不执行YOLO推理线程。在每个40调用块的调用20固定读取来自调用1的检测结果。检测请求仍经过副本中的原请求方法；固定结果只改变隔离副本的检测返回调度。
3. 原`HybridTracker`状态机读取结果，执行真实NanoTrack模板初始化和后续19帧补跟踪。补跟踪是从检测来源帧逐步追到当前帧。调用21至40执行普通Nano更新。每块开始在计时区间外结束上一轮并重置，模型保留。两个完整块预热后才测量。
4. `off`保留现有事件字段准备和关闭分支，`basic`使用原业务发送器及真实独立worker。worker使用CPU4–7、普通调度和原100ms物理存储同步。业务跟踪固定CPU4，外部控制器/资源采样使用0–3。未改变生产CPU策略、频率、模型、Runtime或正式current。
5. 观测组同时记录阶段、局部字段准备、提交和完整调用。局部准备区间覆盖调用入口/返回、历史缓存追加/淘汰/查找、初始化起止、每步补跟踪及汇总等。它不是全部诊断字段准备的完整总和。真正无内部观测组关闭这些观察器及`SubmitMeasurement`，只保留两模式对称的外层完整调用和线程CPU时间计时。
6. 单独audit（数据核对）短组在真实Nano后端入口对模板/搜索输入及Head分类/位置输出计算SHA-256。SHA-256是核对字节内容的指纹。同时逐调用核对框、分数、状态、完整诊断事件顺序摘要和模型调用数。未直接读取共享设备内的搜索特征张量；这一限制必须保留。

计划次序包括off/basic和basic/off各一组观测对照，各一组真正无内部观测对照，以及两组off观察器开启/关闭反序对照。每条件54个完整块，共2160次调用，54次独立长补帧调用，1080次普通更新和1026次检测等待。短audit每条件2块。每组独立systemd控制组运行最长140秒、停止预算5秒、外层总上限150秒。恢复守护在停服前ready；armed使用单调起点，1720秒开始收尾，1800秒包含正式恢复。

完整调用使用`std::chrono::steady_clock`，并核对`CLOCK_MONOTONIC`分辨率。线程CPU时间使用`CLOCK_THREAD_CPUTIME_ID`；墙钟耗时减CPU时间包含多种等待，不能全部归类为NPU或调度。外部每秒读取`schedstat`（线程可运行却未获得CPU的累计等待）、CPU/NPU/DMC频率和温度。`schedstat`不含线程睡眠期间的驱动阻塞。实际不可读取项明示未知。

保留全部原始调用、失败、慢值和未扣减结果。P99使用排序后第`ceil(0.99*N)`个值。按完整40调用块重采样给出分位差的区间；这个区间只反映同一运行内的块波动，不覆盖运行间漂移或任意模型环境。54个独立长调用不足以为该分支真实P99提供有限、分布无关的95%上界。完整调用总体P99和长调用分支P99必须分开报告，不能以2160代替54宣称尾部精度。

最初副本曾使用OpenCV解BGR再转灰度并固定OpenCV线程数1，与正式MJPEG亮度读取不同。该副本的audit记录与超时组全部保留，作为不同输入场景，不混入修正后的比较。初轮80块超过控制器62秒单条件预算，已失败并恢复；缩为54块依据实际耗时，没有延长150秒组上限。
