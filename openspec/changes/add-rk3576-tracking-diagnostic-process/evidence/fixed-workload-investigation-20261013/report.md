# 固定工作量诊断开销调查

日期：2026-10-13。变更：`add-rk3576-tracking-diagnostic-process`。**在同一真实Nano模型实例、同一帧与固定分支下，两次相邻随机对照仍测得basic完整调用P99增加5.341和5.517ms，明显高于0.2ms。额外长调用时间主要表现为非线程CPU区间，尚不能唯一归为调度、NPU驱动或存储。没有找到已证明安全的代码修复。任务7.3仍未完成，CLI保持39/40。**

P99是排序后第`ceil(0.99×N)`个值。本文“固定段”（block）包含40次调用。结果是额外归因证据，不替代正式十组验收。特别是最终随机入口的off期仍保留共享区和空闲worker；没有ROS、采集、bag、HDMI或测量期YOLO并发。因此这些数值不能直接外推完整生产管线或长期总体开销。

## 固定了什么，核对了什么

使用生产板**HZ-RK3576_WuKong Board**，Ubuntu 22.04.5 ARM64、内核`6.1.141-rt36`，RKNN Runtime **2.3.2**、驱动**0.9.8**。系统Runtime使用原`/usr/lib/librknnrt.so`，SHA-256仍为`d31fc19c85b85f6091b2bd0f6af9d962d5264a4e410bfb536402ec92bac738e8`。SHA-256用于核对文件字节。三个模型概念为YOLO、NanoTrack Backbone和Head；Backbone沿用既有FP16模板/搜索两个文件，没有转换或替换模型。

1. 从既有`fixed-balloon.avi`用正式帧源的`MjpegVideoReader`读取首帧亮度。视频SHA为`c25aec33208f5dfca315eb9c2c4fb86b04d98883ec5d74b68f5ac7746a669a95`。图像为Gray8（每像素一个8位灰度值），1920×1200、`CV_8UC1`、stride1920，像素SHA为`ad27883488764165ad633e74a354d9e02e0f29794e55b33d835c28e6d3146115`。OpenCV实际默认线程数1。40帧使用相同像素，时间从1000000µs起，每帧增加16667µs。
2. 在测量前执行真实YOLO，得到框`[755.115234,457.962402,39.9310913,36.562439]`、分数`0.589952648`。测量期间只在调用20固定返回来自调用1的该结果；不执行YOLO检测线程。每段开始重置跟踪状态，保留模型实例。真实`HybridTracker`执行一次模板初始化、19步补跟踪，再执行20次普通更新。补跟踪是用来源之后的历史帧把目标位置推进到当前帧。
3. DCF关闭，历史容量30，YOLO间隔4；KF内参和阈值对齐此前固定视频配置。KF是用于预测运动的卡尔曼滤波器。节点取最新帧、真实异步YOLO来源选择和ROS发布没有进入此入口。
4. audit短组对真实Nano后端模板/搜索输入及Head分类/位置输出计算SHA。两模式包含预热的160条API调用记录逐字节相同。观测组每次调用的事件顺序摘要、框、分数、状态、初始化和补步数也完全相同。最终随机入口在每个固定段持续核对真实API调用**1次模板、39次搜索**及40位置完整框/分数/状态，全部通过。Head是根据图像特征输出目标分类和框参数的模型。设备共享搜索特征张量没有直接读取或哈希；不能称每个设备中间张量都已直接核验。

源码仅改在独立分析副本。真实Nano预处理、模型后端和`HybridTracker`状态机没有改写。原工作区业务代码、另外两个change、正式配置/current均保留。测试假定的检测调度不等于完整异步管线。方法详见[design.md](design.md)，具体模型/全部配置指纹在各窗`protected-before.json`及[artifact-manifest.json](artifact-manifest.json)。

## 同进程随机对照：主要结果

为降低不同进程重载模型、地址布局和连续时间漂移，在同一进程中一次准备Client和共享区。仅测试入口在整段边界切换`active`：off为null，basic为原Recorder指针。Recorder对象一直由Client持有；测量期没有YOLO或其他业务生产线程，切换不与业务调用并发，收尾前恢复原指针。正式节点的启动时固定模式接口没有修改。

每个种子40个相邻对，共80段、3200调用；每模式1600调用、40次独立长调用、800次普通更新、760次检测等待。每对随机选择off/basic或basic/off。段边界对称等待至少100ms，并在250ms内确认全部written/synced位置及双环排空；written/synced分别表示完整写入和成功同步。每段计时外刷出原始partial CSV。两种子全部工作/输出/排空检查通过，最大等待160.327/166.724ms。worker保持真实物理存储、100ms双同步、CPU4–7、普通调度；跟踪CPU4，控制器/资源采样CPU0–3。

内部阶段、事件、准备和submit采样全部关闭。只有两模式对称的外层完整调用/线程CPU计时，以及相同的轻量真实模型调用计数。off仍有共享区和idle worker，这是减少布局差的代价，也是本估计的范围限制。排空与100ms等待不能消除全部缓存、介质或内核状态的跨段影响。

普通更新P99增量为**+0.163931/−0.066904ms**；连续5对区间分别为**[−0.607963,1.217682]/[−0.813952,0.742513]ms**。其0.2ms精确门槛尚未闭合。每模式长分支只有40次，分支P99恰为观测最大值，不能据它提供真实尾部有限的95%上界。整体P99由固定占比的长调用决定；1600不能替代40宣称长尾精度。

## 成本位置与尚未分开的因素

两种子长调用的相邻配对差中位分别为：完整耗时**4.712480/4.943495ms**，线程CPU时间**0.589295/0.569521ms**，完整耗时减线程CPU的差**4.409623/4.440540ms**。普通更新相应差为**0.281006/0.252916ms**、**0.027756/0.027539ms**、**0.234271/0.220629ms**。多数额外时长表现为非该线程CPU区间。这个差包含可运行等待、驱动睡眠、I/O等，不能统一称为NPU或调度等待。

从basic原始事件汇总初始化和19步已有duration字段，覆盖完整长调用中位**99.9648%/99.9640%**；区间外中位**0.194561/0.192755ms**，全部样本最大**0.217604/0.457892ms**。这把主要待查范围收窄到Nano初始化/补步执行期间的影响。**这些是完整Nano步骤区间，可能包含内部诊断准备/emit/提交，不是纯NPU时间。不能据覆盖比例排除全部直接开销，也不能把它与submit区间相加。** off没有同级逐步duration，本文没有扣除模型时间判通过。

两组独立进程观测条件的submit P99分别为5.612/5.451µs。长调用内提交总和中位约96µs，最大分别**353.195/780.452µs**，慢例全部保留。局部字段准备长调用中位约12–13µs，off/basic都有；普通更新约1.2µs。它只覆盖已指定的局部快照，不是全部字段准备总量。已有off仍支付事件准备及部分时间读取，不能把off称为完全移除诊断代码。

CPU与NPU读回分别稳定在policy0=2016MHz、policy4=2208MHz、NPU950MHz；只读温度和原始频率序列保留。DMC频率未从现有devfreq节点取得，不能宣称固定。`schedstat`仅记录线程可运行却未获得CPU的累计等待，不包含驱动睡眠。第一固定组按实际采样时长归一的跟踪等待off/basic约27.02/38.52ms每秒；有明确间接争用路径，但不是对非CPU差的完整分解。

## 交付边界与下一最小验证

独立ARM64镜像编译、真实模型audit、全部有限实验与复算核查通过。没有把既有W6的47/47当作新probe的全套测试。目标容器未提供配置可用的clang-tidy/clangd检查入口；新随机入口已clang-format整理。Jetson、完整真实YOLO/ROS/相机/bag/HDMI并发、长期稳定及断电未执行。`openspec validate --strict`、`git diff --check`通过；没有提交、归档、正式升级或修改任务勾选。

下一最小验证应保持本随机入口、真实Nano、CPU和100ms同步规则，只对诊断worker物理eMMC/临时内存介质做单变量反序，或取得能对齐Nano步骤的调度/驱动阻塞证据并标定采集干扰。临时内存介质只作归因，不能证明持久化满足验收。现有证据不足以安全选择通知、worker核心或同步策略修复；不应调整跟踪算法或通过扣减、删慢样本、放宽0.2ms门槛宣布通过。确认修复后仍须以最终产物执行新的完整十组，保留历史失败。
