## 受控变化与测试方法

CPU 亲和性表示线程允许使用的核心。本轮只把诊断收集器从 CPU 3 改到 CPU 7，并修改相应断言和身份记录。每线程启动及运行读回均校验 CPU 7，采用普通 SCHED_OTHER 调度。共 1089 次收集器观测。CPU 7 仍与 capture 职责共享；这不是独占隔离。

业务职责保持 control/tracking=4、YOLO=5、display=6、capture/recording=7。控制器和 bag 仍允许 CPU 0–3；bag 是 ROS 消息录制文件。温度监视器仍在 CPU 0–2。

YOLO 是检测目标的模型，NanoTrack 是从检测框开始逐帧推进位置的跟踪算法。保留原气球 YOLO 和 FP16 NanoTrack 模型；FP16 表示半精度浮点数。固定视频保持 1920×1200、60 FPS、3900 帧。原画录像关闭，bag 与 HDMI 开启。真实模型短预检执行 ON/OFF、关闭 HDMI，并确认收集器 7 和原业务核心。没有用协议版本查询代替模型预检。

全新十组各自交替 off/basic 顺序。off 表示关闭诊断，basic 表示基础诊断。每模式预热四秒、测量四十五秒。独立 systemd 控制组约束该组全部后代进程；控制组是操作系统管理的一组进程。单组运行截止 140 秒、停止预算五秒，外部总上限 150 秒。实际各组总时间为 108.465524–110.724682 秒。

P99 是排序后 99% 样本不超过的耗时。保持原要求：提交 P99≤20 μs，完整调用 P99 增量≤0.2 ms，消费帧率下降≤1%，健康诊断无缺口。至少八组分别满足全部条件。没有删去慢样本、补挑通过组、扣减模型时间、改变算法或放宽阈值。
