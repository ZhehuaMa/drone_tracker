## 实验条件与有效性

CPU 亲和性表示一个线程允许使用的 CPU 核心。收集器在启动时和运行期间读回每线程亲和性，1092 次进程观测均只允许 CPU 3，采用普通 SCHED_OTHER 调度。CPU 3 没有被独占隔离；控制器和 bag 仍沿用原测试的 CPU 0–3 范围。bag 是 ROS 消息录制文件。

业务职责核心保持 control/tracking=4、YOLO=5、display=6、capture/recording=7。YOLO 是检测目标的模型；NanoTrack 是从初始检测框逐帧推进目标位置的跟踪算法。模型仍为原气球 YOLO 与 FP16 NanoTrack 模型，FP16 表示半精度浮点数。视频保持 1920×1200、60 FPS、3900 帧。原画录像关闭，bag 和 HDMI 开启。实际 YAML、环境和模型摘要全部保存。

真实模型短预检执行 ON/OFF，HDMI 关闭；收集器 CPU 3 和业务核心读回通过。之后使用全新目录执行完整十组，off/basic 顺序逐组交替。off 表示关闭诊断，basic 表示基础诊断。每模式预热四秒、测量四十五秒。每组由独立 systemd 控制组约束后代进程；控制组是操作系统统一管理的一组进程。单组运行截止 140 秒、停止预算五秒，外部上限 150 秒。实际各组总时间 108.525241–110.467978 秒。

P99 是排序后 99% 样本不超过的耗时。门槛保持：提交 P99≤20 μs，完整调用 P99 增量≤0.2 ms，消费帧率下降≤1%，健康日志无缺口。至少八组必须各自同时满足全部条件。没有选组补测、删除慢样本、扣减模型时间或放宽门槛。

## 温度与频率

独立监视进程绑定 CPU 0–2，每秒读取一次温度与 CPU/NPU 频率。测量期间只写入 `/run` 下的内存文件系统，结束后才复制到证据目录，避免在测量期间增加监视器的 eMMC 写入。它没有更改时钟、调速策略、优先级或散热设置。监视器本身的开销没有独立标定，不能称为零开销。

完整序列共 1116 个样本，最大相邻间隔 1.001092451 秒。`thermal-summary.json` 还按每个 off/basic 实际测量窗口分别汇总；每个窗口都有 45 个温度/频率样本。下面保留传感器原始类型名称：
