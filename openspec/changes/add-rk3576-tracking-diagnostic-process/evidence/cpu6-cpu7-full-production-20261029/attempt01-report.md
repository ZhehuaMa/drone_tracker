## 测试观察器修订

首轮存在两项独立于生产跟踪算法的观察器问题：

1. 原提交测量数组对每个生产者固定预留 49152 项。首轮完整运行产生的 Node 提交超过这个容量。后续新批次预先改为 6 秒预热、45 秒测量，给采样容量留出余量，不改生产 C++ 或增加诊断内存预算。
2. 资源采样在合成输入发布循环中每秒同步扫描进程和传感器，造成发布间隔长尾。后续把它移到独立的实验控制进程，继续运行在 CPU 0–3，并记录实际输入频率和漏过时隙。不会向业务进程增加日志线程。

初始方案原文和全部原件保留。新的八轮使用 `batch02-` 前缀，核心顺序仍为 6、7、7、6、7、6、6、7；每轮由不同新建子代理执行。不会把首轮样本拼入新批次，也不会因性能结果不利而补挑样本。正式录像分段仍为 60 秒，短窗口不承诺覆盖分段切换。

具体方案见 [protocol.md](protocol.md)，原方案见 [protocol-initial.md](protocol-initial.md)。独立复算程序 [compare_runs.py](compare_runs.py) 已对首轮实际 CSV、基础事件和资源数据复算，结果见 [attempt01-independent-analysis.json](attempt01-independent-analysis.json)。当前有效比较轮数为 CPU 6：0，CPU 7：0。
