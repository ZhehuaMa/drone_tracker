## 本轮配置与运行边界

用户明确要求把收集器绑定到 CPU 3。CPU 亲和性表示线程允许使用的核心；本轮收集器只允许使用 CPU 3。它不是把 CPU 3 从内核或其他程序中独占隔离。控制器和 bag 仍沿用原测试的 CPU 0–3 范围；bag 是 ROS 消息录制文件。

业务核心映射保留：control/tracking=4，YOLO=5，display=6，capture/recording=7。YOLO 是寻找目标的检测模型。NanoTrack 是从检测框开始逐帧跟踪目标的算法。本轮保留原气球 YOLO 和 FP16 NanoTrack 模型；FP16 表示模型使用半精度浮点数。

输入保留原固定视频，1920×1200、60 FPS、3900 帧。原画录像关闭，bag 与 HDMI 开启。每组 off/basic 顺序交替，各预热 4 秒、测量 45 秒。没有放宽提交 P99≤20 μs、完整调用 P99 增量≤0.2 ms、消费帧率下降≤1%和无诊断缺口的要求。

测试脚本只修改收集器启动的核心范围，增加每线程亲和性读回，并调整独立守护为结束后保持正式跟踪服务停止。修改见 `harness.patch`。业务二进制逐字节不变。

真实模型短预检通过。预检确认收集器 CPU 3 和业务职责核心。每组由 systemd 控制组约束后代进程，单组运行截止 140 秒、停止预算 5 秒，外部总上限 150 秒。控制组是操作系统统一管理的一组进程。独立守护设置 1720 秒开始清理、1800 秒总截止。

用户授权正式服务可保持停止。本轮在完整批次启动时停止了正式跟踪服务，并把守护动作改为保持停止，而不是自动恢复运行。原正式版本、配置、模型和系统 Runtime 没有在准备阶段改写。没有禁用其下次开机启动；断线后的实际服务状态和文件身份仍待核验。
