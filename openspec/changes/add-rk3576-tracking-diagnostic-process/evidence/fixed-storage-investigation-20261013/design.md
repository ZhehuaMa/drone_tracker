# 固定工作量存储对照设计

日期：2026-10-13。目标是在生产 HZ-RK3576_WuKong Board 上判断：只把基础诊断记录的物理 eMMC 目录改为 tmpfs，是否改变固定真实模型调用的完整耗时及非线程 CPU 时间。tmpfs 是内存文件系统，其同步调用保留操作系统接口，但不提供断电后持久化。本实验不替代任务 7.3 的完整十组验收，也不改变 0.2 ms 门槛。

## 选择与范围

选择一个长期运行的业务进程、一个 Client（共享区域的所有者）、一个 Recorder（提交事件的对象）、一个共享区域和一个长期运行的日志 worker。worker 在完全排空且已同步的段边界更换独立 Storage 对象。Storage 是负责文件记录、校验和双同步的现有组件，其构造函数从共享区域的 synced 位置继承已经确认的生产者序号。没有重连、重启模型或重置生成位置。拒绝每段重启业务，因为模型实例和地址会变化。也拒绝两个客户端，因为共享区域地址和空闲日志消费者会成为额外条件差异。

仅独立实验源码副本增加显式 `--test-switch-control` 和 `--test-tmpfs-directory`。原工作区生产代码、正式配置及 current 不变。Storage 的实际写入、递归目录空间保护、CRC 校验和 100 ms 双同步代码不变。CRC 是检查记录字节损坏的校验值。切换前写入正常 End 记录并完成双同步；之后关闭旧文件，在新段目录打开新文件，保存身份，建立初始提交记录，再回应确认。各段使用单独目录，避免两介质累计目录数不同影响每次空间检查。序号在共享区中持续增长，每段检查提交记录连续性。

健康记录仍沿用 worker 的实际协议。新段把健康周期起点重置为当前单调时间，使两条件都从同一周期相位开始。它不删除已有事件或关闭同步。健康字段中的同步耗时、位置和时间按事实保留。业务序列应逐段有相同类型、顺序、有效字段和事件数；绝对时间、运行身份和连续序号允许不同。实际健康记录和提交批次数因执行及调度时间不同而可能变化，必须分别报告，不冒充字节完全相同。

## 实验顺序

1. 生产运行期间完成源码、构建、传输和无模型协议预检，核对系统 Runtime、真实挂载来源和可用内存。
2. 独立恢复 guard 就绪后才记录 current、全部配置/模型和 Runtime 指纹并停服。维护总预算 1800 秒，1720 秒开始恢复。
3. 使用原正式 MJPEG 首帧亮度契约，真实 YOLO 在计时前检测一次。每 40 调用段在调用 20 返回来源调用 1 的固定结果；真实 Nano 执行 1 次模板与 39 次搜索。模型实例、参数、像素、状态机和 OpenCV 默认线程保持不变。两个完整块预热，保留原始记录。
4. 每段完成业务后关闭 active 指针；等待至少 100 ms，最多 250 ms，核对全部 generated/written/synced 一致、普通/关键环为空且无错误。generated/written/synced 分别是生成、完整写入、已成功双同步的生产者位置。
5. 通过 tmpfs 控制目录原子发布目标段号和介质。worker 验证严格递增段号、无缺口及排空条件。切换确认最多 500 ms，再对称等待 100 ms。设置同一个 Recorder 指针，然后重置跟踪状态并执行完整段。切换成本在完整调用计时外。
6. 每种子 32 个相邻对；每对随机选择 eMMC/tmpfs 或 tmpfs/eMMC。两独立种子为 20261013 和 20261014。仅对称外层墙钟与线程 CPU 计时及真实 API 次数检查进入测量。内部阶段/提交/事件观察器关闭。短 audit 独立核对模型输入及最终 Head 输出 SHA；设备特征张量不直接读取。
7. 每段在计时外保留 partial CSV。每组 systemd 控制组最长 140 秒，停止预算 5 秒，外层含导出和恢复检查最长 150 秒。全部慢值与失败保留。结束后立即恢复正式服务，再进行离线分析。

跟踪 CPU4；worker 实际所有 TID 允许 CPU4–7，普通 SCHED_OTHER 调度；控制/采样 CPU0–3。TID 是线程编号。没有测量期异步 YOLO、相机、ROS、录像、bag 或 HDMI。active 指针从不超过 Client 生命周期，切换没有并发业务生产者。测试专用 tmpfs 挂载最多 128 MiB，保留空间保护，同步协议不关闭。原件先复制到 eMMC 并核对 SHA，再清理精确实验挂载路径。

## 判读边界

比较原始完整调用 P99、长初始化/补跟踪调用、普通更新及线程 CPU 与非 CPU 时间。P99 是排序后第 `ceil(0.99×N)` 个样本。墙钟减线程 CPU 包含运行等待、驱动睡眠和其他阻塞，不能全称 NPU 时间。相邻对重采样、连续 5 对重采样及实际排列随机化检验只描述本次运行；32 个长调用不足以给真实尾部提供分布无关上界。

存储切换也改变文件系统元数据、目录保护遍历、写入和同步行为。如果 tmpfs 显著减少额外非 CPU 时长，可支持物理持久化相关路径的贡献；不能只归因 fdatasync 系统调用。如果结果无变化，则削弱这一假设，不能排除全部 I/O 或调度影响。既有 off/basic 结果仅作为背景，不从新结果扣减模型时间或常数宣布验收通过。没有新 off 条件，因为本次最小问题只比较两种存储介质。
