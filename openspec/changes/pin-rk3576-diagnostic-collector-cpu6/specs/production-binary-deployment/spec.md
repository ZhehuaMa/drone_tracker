# 生产部署规格增量：诊断收集器固定 CPU 6

## ADDED Requirements

### Requirement: 诊断收集器启动固定到 CPU 6

CPU 亲和性表示进程允许运行的核心集合，不表示独占核心。诊断服务和直接诊断入口 SHALL 在启动收集器工作前，将收集器自身的实际允许集合确认为 `{6}`。两种入口 SHALL 读取同一已安装共享 CPU 策略，并要求其中允许 CPU 6。成功记录 SHALL 包含请求集合与实际读回集合。收集器 SHALL 保持普通 `SCHED_OTHER` 调度，即现有非实时调度方式。

#### Scenario: 服务使用生产策略启动
- **WHEN** 已安装策略允许 `[4, 5, 6, 7]`，维护者启动诊断服务
- **THEN** 收集器工作前读回允许集合 `{6}`，日志记录请求与实际集合均为 `{6}`，调度为 `SCHED_OTHER`

#### Scenario: 直接入口与重新启动一致
- **WHEN** 维护者通过直接入口启动收集器，或诊断服务退出后重新启动
- **THEN** 每个新收集器在工作前重新确认实际集合 `{6}`，不会恢复为完整共享范围

### Requirement: 诊断核心校验失败拒绝启动

共享策略不允许 CPU 6、CPU 6 不可用、亲和性设置失败或读回集合不是 `{6}` 时，诊断入口 SHALL 返回非零并明确报告诊断不可用。失败入口 MUST NOT 执行收集器程序。入口 MUST NOT 静默选择其他核心或修改共享策略以满足绑定。

#### Scenario: 共享策略排除 CPU 6
- **WHEN** 其他方面有效的共享策略仅允许 `[4, 5, 7]`
- **THEN** 诊断入口失败并指出 CPU 6 不在允许范围，收集器没有执行，策略文件内容不变

#### Scenario: 系统拒绝或错误读回
- **WHEN** 操作系统拒绝 CPU 6 绑定，或设置后读回为 `{6, 7}`
- **THEN** 入口非零退出并报告具体错误，不执行收集器，也不回退到 CPU 7

### Requirement: 收集器绑定不改动其他执行单元

收集器绑定 MUST NOT 改变其他既有进程或线程的 CPU 亲和性。绑定 MUST NOT 改写共享允许范围或业务职责映射。业务启动入口、优先级、系统调频和内核核心隔离 SHALL 保持既有行为。CPU 6 上已有显示线程 SHALL 继续使用 CPU 6。诊断失败 SHALL 保持既有业务独立运行和诊断退化行为；退化表示诊断不可用时业务继续。

#### Scenario: 保留生产业务映射
- **WHEN** 收集器通过服务或直接入口成功启动，生产策略使用既有职责映射
- **THEN** 共享允许范围仍为 `[4, 5, 6, 7]`，控制与跟踪仍为 CPU 4、检测仍为 CPU 5、显示仍为 CPU 6、采集与录像仍为 CPU 7

#### Scenario: 保留旁路进程和调用方
- **WHEN** 一个已有旁路进程和调用方保持运行，随后分别启动并停止两种入口的诊断收集器
- **THEN** 旁路进程、其既有线程和调用方的允许集合保持启动诊断前的值，不继承收集器的 `{6}`

#### Scenario: 诊断无法绑定时业务继续
- **WHEN** 业务已正常运行，而独立诊断入口因 CPU 6 不可用而失败
- **THEN** 业务进程仍存活，其原有 CPU 策略不变，沿用既有诊断不可用处理
