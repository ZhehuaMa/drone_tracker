## 依赖隔离与静态检查

`file` 确认三个工具均为 ARM aarch64 ELF。`readelf -d` 检查回放工具的直接依赖，包括 OpenCV、RKNN、Crypto 和系统运行库，无 CUDA、TensorRT、VPI、Tegra、ROS。公共算法静态库用 `nm -u` 检查，不包含上述平台 SDK 的未定义符号。`replay_tests` 不链接 RKNN；两个旧 probe 不链接 Crypto。根目录平台选择拒绝测试继续通过。

对变更的 C++ 翻译单元运行 `clang-tidy` 的 `clang-analyzer-*` 检查，使用 `.docker-artifacts/replay-lint/compile_commands.json`，诊断日志在同目录。检查数据库复用本地既有 OpenCV/RKNN 头文件和 macOS SDK，仅用于静态检查，不能代替 ARM64 构建。

同时执行本地 clangd `--check`。它未报告源码解析或类型错误，但其逐 token 重构功能自测报告 `ExtractFunction`/`ExpandDeducedType` 失败。因此不宣称 clangd 全部检查零错误；这些工具功能自测信息保存在 `.docker-artifacts/replay-lint/clangd.log` 和 `clangd-runner-detail.log`，与编译及静态分析结果分开陈述。

## 实现与工件核验

- `ModelPaths` 保留原前三字段，只追加模板和搜索路径；装配按显式角色加载，不推断文件名。组件携带同次查询的描述，不再次加载模型取得报告。
- `TrackerSettings` 的旧模型路径字段在解析结果中清空，模型装配只读取 `ModelPaths`。所有运行参数显式映射，不读取其他设置文件。
- CSV 帧时间及预测时间相同；旋转矩阵使用公共上下文的单位阵默认值。墙钟调度与算法时间分离。
- 为保证每帧诊断准确，在 `update` 入口清空上一帧 NanoTrack 框和分数。这只修改诊断值，不修改模板、滤波器、阈值、仲裁或状态数值。
- JSON 所有计数和帧号统一采用十进制字符串；无样本统计为 null。长模型属性按行存放，避免 OpenCV 长字符串限制。该编码由 `report_version` 与 `integer_encoding` 说明。
- 配置通过后先建立 running 报告，使文件指纹或录像初始化失败也能留下失败记录；模型初始化仍在视频首帧及元数据验证之后。无效配置不创建目录，也不加载模型。
- 输出检查包含刷新和关闭。普通失败后先销毁跟踪器、等待检测线程，再写最终汇总；未完成汇总不伪装为成功。
- 已有两个 probe、生产 ROS 参数、根目录平台拒绝规则及混合精度后端支持保留。
- `openspec validate assemble-rk3576-tracker-replay --strict` 已通过；未执行任务有明确用户指定的实机边界。
